# Airborne regime posterior: computational validation

The new [development protocol](geometry-air-regime-posterior-protocol.md) preserves recorded Ground versus Air and standardizes only airborne subtypes. It replaces the failed pooled translation's fixed smoothing with a hierarchical probability model that shares information between represented early and late recording regimes. Each recorded-subtype/result cell has its own global composition and two regime-specific distributions. No new real-data predictive scores have been produced by this computational validation.

An unscored smoke on the existing 9,869 eligible events tested 11 independent cells at concentrations 3, 30, and 300, including zero-count absent regimes. All 33 integrations agreed between quadrature orders 64 and 128 to the declared `1e-5` moment tolerance; the largest discrepancy was `1.864e-8`. An earlier diagnostic incorrectly treated all cells as regimes of one global composition; it was replaced before predictive scoring. That diagnostic's concentration-300 numerical failure does not describe the intended cell-specific model.

The frozen simulated-recovery experiment generated 200 datasets per concentration, or 600 total, from the declared hierarchy. Each dataset had two regimes with 20 and 200 training events, followed by 100 future events per regime. Using 4,096 posterior draws, nominal 95% intervals covered latent regime class probabilities in 92–97% of datasets across the 18 concentration/regime/class slices. Future-count intervals covered in 94–98.5%. Every slice passed the necessary 90% computational screen. Per-slice Wilson intervals and widths are retained; the screen does not prove exact nominal coverage. Replicated counts conserved their event totals.

Evidence is retained in `artifacts/statistical/backtests/geometry_reliability/20260911-air-regime-recovery-v2`, including the protocol and code snapshots, package versions, deterministic seeds, all simulation interval records, checkpoint log, summary, and file hashes. The earlier v1 run remains preserved; v2 repeats it after an explicit type annotation at the SciPy array boundary. This is recovery under the assumed generative model. It neither validates historical recording assumptions nor resolves unknown Statcast measurement provenance.

The separate tail check compared orders 128 and 256 for all 11 cells and three concentrations using four 16,384-draw repeats. Sparse reached-on-error cells had the largest sampling variation. Focused 262,144-draw checks reduced the largest cross-order difference to 0.00446 in a probability interval endpoint and one event in a 100-event count interval. Deterministic mixture-CDF endpoints for the two worst sparse probability cases agreed within `9.33e-15`, supporting numerical stability of those tails. The remaining one-count predictive difference is unresolved at Monte Carlo and integer-quantile resolution. Finite posterior draws must therefore retain a sampling-resolution qualification; moment stability alone is insufficient. Tail evidence binds the pre-annotation kernel; the annotation leaves numerical operations unchanged.

The frame-facing implementation enforces supported regimes, Ground preservation, masked-input abstention, explicit prior-only unseen cells, and shared cell/regime draws. It passes 34 focused tests; the broader statistical suite passed 1,168 tests with 18 slow tests deselected and eight dependency deprecation warnings. Ruff passes. Combined strict type checking passes with checker-only SciPy stubs in a temporary directory and a kernel-scoped exception for redundant-instance diagnostics on intentional runtime argument validation. Project dependencies are unchanged. These software checks are separate from scientific acceptance.
