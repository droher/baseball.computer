# Retrosheet scorer provenance contract

`retrosheet-scorer-keys-v1` preserves two Retrosheet game-header keys as separate nullable strings:

- `official_scorer` is the complete decoded value from `info,oscorer`.
- `source_scorer` is the complete decoded value from the administrative `info,scorer` key.

Neither field falls back to the other or to `scorer`. A missing or blank key is `NULL`. A retained `Unknown` or `?` sentinel has `observed_status = unknown_code`; other nonblank values are `observed`. Values establish their source key, not a validated person identity.

The existing `scorer` column remains an ambiguous compatibility field. Its historical value follows the parser's legacy last-record behavior across both keys. `game_scorekeeping`, `affiliated_team`, and existing scorer model inputs retain that legacy behavior in this transition. They cannot support official-scorer identity claims. New identity-aware analysis must use `official_scorer` and must perform a separate identity validation step. `source_scorer` must not enter person-identity normalization.

The external source declarations and `stg_games` reference both new columns directly. The local pre-change `event/games.parquet` (`be90a9762af2e009db615bfce6c554d54a4d7bf9e293c4ff5d027a8fb581fab1`) and `event/box_score_games.parquet` (`78652e4c0522f175c47e846661965a619c716657a569136b23fba0b1d889f9fd`) contain legacy `scorer` and lack both new columns. Current published source tables predate this contract as well, so model evaluation fails closed until both source families are regenerated by a parser that emits the new schema. No production rebuild or promotion is part of this development change.

`game_context_observation_ledger` exposes independent `official_scorer` and `source_scorer` rows. `event_observation_context` carries both raw values and their statuses. Its existing aggregate `context_confidence` deliberately excludes these two new dimensions so the additive schema transition does not silently demote historical rows; consumers opt into the source-specific statuses explicitly.

The local raw-corpus verification surface on 2026-09-11 was `/Users/davidroher/Repos/baseball.computer.rs/retrosheet` (8,726 files, 2.1 GB). Existing parser outputs were `/Users/davidroher/Repos/baseball.computer.rs/event` (314 MB). The original parser checkout had debug and release binaries under `target`, while the patched development binary was under `/private/tmp/bc-scorer-parser-20260911/target/debug`. Binary presence does not prove which schema produced an existing parquet, so verification must inspect the parquet schema or regenerate to a new output directory.

A header-only overlay is recorded at `artifacts/statistical/backtests/geometry_reliability/20260911-scorer-header-overlay-v1`. It binds the preselected 373 TRAIN fitting games by the SHA-256 digests of `selected_fitting_games.parquet` and `local_fitting_events.parquet`, projects only `game_id` and legacy `scorer` from the latter, and scans only `id`, `info,oscorer`, and `info,scorer` records from 120 individually hashed raw files. All 373 games had one `oscorer` record, no `scorer` record, no duplicate source block, and an exact match between the raw last-key survivor and existing fitting metadata. This overlay can supply source-specific official-scorer metadata for that bounded fitting set. It does not modify the immutable fitting artifact or establish scorer coverage outside those games.

The [full-corpus repair validation](scorer-source-repair-validation-2026-09-11.md) also fixes nondeterministic duplicate selection and single-thread termination. Under the same deterministic source-selection policy, the baseline and scorer-repaired builds preserve all legacy values across all 30 exported tables. Corrected local game Parquets are available for isolated validation; published sources still require a separate compatible release.
