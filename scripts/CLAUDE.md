# Publish pipeline

- `publish_ducklake.py` copies `main_models.*` + `main_seeds.*` out of a read-only `bc.db` attachment into the `bc_publish` DuckLake catalog (`bc/bc_publish.ducklake` + `bc/bc_publish_data/`). ENUM columns cast to VARCHAR — DuckLake v1.0 doesn't preserve user-defined types. It then creates the `semantic` views (`bc/semantic/_views.py`) and the `metrics` macros (`bc/python_models/metrics/sql_render.py`) in the same catalog and regenerates `docs/llm/baseball.lsf` with `generate_llm_context.py --validate`. `--semantic-only` redoes only the views, macros, and packet. Every mode ends by expiring all but the latest snapshot and deleting the local data files no snapshot references (`KEEP_LAST_N_SNAPSHOTS`), so the local export never accumulates history.
- `generate_llm_context.py` builds the LSF-1 packet from the SQLMesh context, the metric registry, `docs/llm/supplement.yaml`, and the franchise and park seeds (team, park, and league ENUM records). `METRIC` expressions and macro bodies both come from `sql_render.py`, and the publisher deletes the old packet before regenerating, so a failed regeneration leaves no packet to upload instead of a stale one. `bc/tests/test_verified_queries.py` runs every supplement query against the local export under `-m slow`.
- `publish_ducklake.py` refuses (SystemExit) when any estimated table listed in its `ESTIMATED_ROW_COUNT_FLOORS` is below its floor in `bc.db`. The floors mirror the `min_row_count` audit each coverage `@model` declares (`bc/audits/min_row_count.sql`); `bc/tests/test_publish_ducklake.py` asserts the two stay identical and that every estimated table is either floored or documented empty (`pitch_count_coverage`, `imputed_advancement_probabilities`).
- `check_published_pointers.py` is the CI gate before SQLMesh planning. It requires `BC_STATS_ARTIFACTS_ROOT`, reachable pointers including pretrain subdirectories, explicit publication mode, current content-bound reports, and valid dependency evidence. Legacy unbound pointers fail and require reviewed migration. See [modeling evidence contract](../docs/modeling-evidence-contract.md); do not run a global write sweep to bypass migration.
- CI artifacts root. `artifacts/` is gitignored, so the workflow's `actions/checkout` tree has no published pointers and every coverage `@model` would materialize its typed empty frame. The workflow exports `BC_STATS_ARTIFACTS_ROOT` from the GitHub Actions repository variable of the same name; set it on the repo (Settings → Secrets and variables → Actions → Variables) to the absolute path of the canonical artifacts directory on the self-hosted runner's machine, e.g. `/Users/davidroher/Repos/baseball.computer/artifacts/statistical`. The published pointers store absolute `manifest_path` values under that directory, so the runner's separate checkout resolves the same artifacts as local prod. `python_models.statistical.config.resolve_artifact_root()` reads the variable; `BC_STATS_GLOBAL_PUBLISHED_ROOT` (tests) and `BC_STATS_PUBLISHED_ROOT` (per-branch dev recipes) still take precedence for pointer lookup when set. A pointer written with `write_published_pointer(..., relative=True)` stores `manifest_path` relative to the artifacts root and is resolved back by `read_published_pointer`.
- `upload_ducklake.py` ships catalog + data dir + `baseball.lsf` to `s3://timeball/baseball/v<DATA_VERSION>/` with immutable Parquet files, revalidating catalog/schema/packet metadata, and a Cloudflare cache purge. It validates the packet before uploading anything, and it creates or updates the Cloudflare `DuckLake metadata revalidation` cache rule through the API so the rule always lists the objects being published (`--skip-cache-rule` to bypass; the token needs Cache Rules edit). After the purge it HEADs the metadata URLs and fails on an edge cache HIT. OAuth-only publishing uses `--wrangler`; `--skip-purge` is suitable for a fresh version prefix.
- The production site attaches the public DuckLake catalog read-only. `catalog.json` is generated from that same DuckLake for the schema sidebar. The legacy `/dbt/` objects remain for external consumers and rollback; no new site publication depends on them.
- `preload_sources.py` is the only ad-hoc script allowed to write `bc.db` directly (only `CREATE TABLE IF NOT EXISTS`). Everything else goes through SQLMesh.

# Research materialization

- `materialize_geometry_research.py` creates an APFS copy-on-write clone of the production database and SQLMesh state, then builds the corrected geometry ledger and its two modeling views in an isolated development schema. It attaches only the clone, disables source initialization and publication hooks, and records production identities before and after the build. Use a new output directory and environment for each research snapshot; `--resume` is only for an interrupted isolated build. See [corrected geometry refits](../docs/geometry-corrected-refits-2026-09-11.md) for the completed run and fitting commands.

# Pretrain orchestration

- `run_pretrain_residual.sh STAGE1_ID STAGE2_ID` — residual-decomposition pretrain orchestrator. Prep dataset → stage-1 fit on context-only spec → emit per-head logit offsets → stage-2 fit on full spec with `BC_PRETRAIN_OFFSET_ARTIFACT` → publish branch-scoped pointer. Env: `BC_PRETRAIN_DATASET_ARTIFACT`, `BC_PRETRAIN_STAGE1_EPOCHS`, `BC_PRETRAIN_STAGE2_EPOCHS`, `BC_PRETRAIN_SKIP_PUBLISH`, `BC_PRETRAIN_DATASET_LIMIT` (smoke), plus `BC_PRETRAIN_LOSS=focal`, `BC_PRETRAIN_USE_HARD_HEAD_ES=1`, `BC_PRETRAIN_HARD_HEADS=...`. Architecture in [[pretrain-architecture]].
- `pretrain_emit_offsets.py <stage1_artifact_id> --dataset-artifact <id>` — load a saved stage-1 pretrain model, build an inference submodel exposing per-head `{head}_logits` Dense layers, stream the dataset through `.predict()`, write float16 per-head parquet (`event_key, logit_0..logit_{K-1}`) under `<stage1_artifact_dir>/offsets/`. Respects `BC_PRETRAIN_DATASET_LIMIT` and the spec's `row_filter_predicate`. Loads model with `compile=False` (loss-config deserialization isn't needed for inference; also avoids registration issues with closure-returned focal loss).
- `run_permimp_compare.sh` / `run_permimp_batted_ball.sh` — perm-imp acceptance-gate runners. The first does baseline-vs-pretrain on `geometry_trajectory`; the second sweeps the 3 geometry location targets (`location_side` / `_depth` / `_edge`). Both invoke `permutation_importance_generic.py` and set the env knobs needed to consume the active pretrain (`BC_DEEP_FORCE_EMBED_DIM=128`, `BC_PRETRAIN_SKIP_DIM_MISMATCH=1`). `PUB_ROOT` is derived from the current git branch so the published-pointer resolution survives merge into other branches.

# Permutation importance

- `permutation_importance_generic.py` — fit a deep target on its FeatureLayout and report per-feature Δ_CE on a held-out slice. Use to derive per-supplement acceptance-gate floors (`BC_DEEP_DISABLE_PRETRAIN=1` for no-pretrain baseline; unset for the pretrained arm). Flags / env:
  - `--target` / `PERMIMP_TARGET` — deep target name (e.g. `geometry_trajectory`).
  - `--dataset-parquet` / `PERMIMP_DATASET_PARQUET` — fully qualified parquet path.
  - `--time-forward` — eval on `time_forward_fold` instead of the spec's default `primary_fold`. Use for Phase-3 gates so the slice matches production temporal eval.
  - `--val-filter` / `PERMIMP_VAL_FILTER` — extra SQL predicate applied to the VALIDATE rows post-partition.
  - `--full` / `PERMIMP_FULL=1` — disable train/val subsampling.
  - `--epochs` / `PERMIMP_EPOCHS` — override fit epochs.
- `permutation_importance_trajectory.py` — trajectory-only wrapper kept as a smoke-runner. Use the generic script for any new supplement.
