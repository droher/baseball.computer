Oracle-offset arm of the MNAR masked backtest (`bc/python_models/statistical/backtests/mnar_masked.py`) run against four registered synthetic mask designs, geometry/trajectory variant, smoke budget (`SMOKE_BUDGET=1000`, 50 draws × 50 tune × 2 chains), seed 20260610. `w_class_intensity` is the harness's original design (class × salted-game-hash-bucket intensity); `covariate_joint`, `scorer_blocked`, `era_graded` are the three robustness designs added for referee major 2. The offset applied in every row is the design's own oracle (see "oracle form"), evaluated per `evaluate_offset_arm` against `THRESHOLDS` (`focal_relative_reduction_min=0.25`).

**Read before using any number below.**

1. For `w_class_intensity`, `scorer_blocked` and `era_graded` the oracle-offset arm's recovery is an algebraic identity at the marginal level: when selection depends on class alone (or on nothing), `P(c | masked) ∝ P(c | observed) · odds_mask(c)` holds for any per-event shares, including a constant model, so reweighting by the realized per-class masked rate recovers the masked-slice marginal by construction and cannot fail. The ≈exact and ≈no-op verdicts on those three rows are consequences of the design, not evidence about the offset. Only `covariate_joint` (relative reduction 0.537) tests the offset against a selection process it does not already encode, and it is the one informative row.
2. Every number here comes from a `SMOKE_BUDGET=1000` run (50 draws × 50 tune × 2 chains). The convergence gates fail on all four designs (`ess_bulk_min` 20–47 against the 100 floor; `overall_pass` False everywhere). The regeneration commands at the bottom carry `--smoke` for that reason, and no run artifacts (`metrics.json`, `mask_summary.json`) are checked into the repository; the numbers quoted here cannot be re-checked without rerunning.
3. Sign convention for the learned `gamma_propensity_class` arm (the negative control, not in this table): `z` is the standardized logit of `propensity_p_observed`, so masked events have low `z`, and a negative GroundBall coefficient raises GroundBall on the masked slice, which is the direction a correction needs. The learned arm's −0.001 relative reduction means it is inert on the masked slice, not wrong-signed.

Every run's `overall_pass` / `offset.pass` gate reads `False` for all four designs at this smoke budget (`ess_bulk_min` 20–47 vs the gate's 100 floor at 100 total post-warmup draws; `rhat_max` ≤ 1.12 everywhere). The offset arm's share arithmetic does not depend on the sampler, but the fits these shares come from did not converge, so the table is a smoke-budget check of the mechanism, not a publication-grade result. `scorer_blocked`'s `offset.criteria.focal_share_error_reduced` reads `False` for a different, correct reason: the 0.958/0.995/0.537 relative reductions above clear the 0.25 floor, but scorer_blocked's 0.015 does not — there being (almost) nothing to correct is the expected outcome for that design, not a defect in the offset mechanism.

Absolute TV is not comparable across designs (each mask realizes a different uncorrected bias scale); relative reduction is the comparison axis. The ordering w_class_intensity ≈ era_graded > covariate_joint ≫ scorer_blocked follows from item 1 above: the three class-only designs sit at the identity's two limits (≈1 when class selection is present, ≈0 when it is absent), and only `covariate_joint` lands somewhere informative.

Design-realization checks, from each run's `mask_summary.json`: `covariate_joint` resolved covariate column `batter_hand` (values `{"L", "R"}` in production), realized an overall masked share of 0.7120 (target `overall_masked_target=0.70`), and realized `masked_share_by_covariate_level` 0.490 (level 0.70) vs 0.872 (level 1.30) — the class × covariate interaction is present, not just a marginal level shift. `_covariate_bucket` assigns the two hand values to different buckets by sorting the distinct values and using `rank % 2`, not a salted hash into 2 buckets — a hash split was tried first and silently degenerated on this exact column (both real `batter_hand` values landed in the same hash bucket, leaving only the ~0.07% null rows in the other bucket, which is what a first pass of these results showed before the fix). `scorer_blocked` blocked 58,561 / 79,822 maskable games (0.734), matching the design's target `overall_masked_target / block_probability = 0.70 / 0.95 ≈ 0.737`. `era_graded` realized the same per-class `class_mask_probabilities` as `w_class_intensity` (0.659 non-focal / 0.754 GroundBall) by construction — only the intensity-bucket assignment mechanism differs (season quantile vs salted game hash).

The numbers above come from `metrics.json`'s `offset` block (`focal_share_error.uncorrected` / `.offset` / `.relative_reduction`, `tv.uncorrected` / `.offset`) and `mask_summary.json`'s design-specific fields (`covariate_column`, `masked_share_by_covariate_level`, `block_probability`, `n_blocked_games`, `n_total_maskable_games`).
