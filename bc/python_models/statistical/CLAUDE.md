# statistical/ — data-coverage statistical pipeline

Owns Phase 0–5 of the data-coverage initiative (`notes/data-coverage-implementation/`). The Phase-3 deep package (`deep/`) is the most recently expanded surface.

## Layout

- `cli.py` — `bc-stats` CLI. Subcommands: `prepare-dataset`, `run-eda`, `check-split-leakage`, `check-publication-gate`, `fit-deep`, `fit-pretrain`, `fit-bayes`, `publish-pretrain`, `publish-manifest`, `validate`. The fit-deep handler lazy-imports keras and the fit-bayes handler lazy-imports pymc inside the function body so `bc-stats --help` stays Torch- and PyMC-free.
- `dataset_registry.py` — per-dataset metadata for the eight `main_models.model_input_*` views. Most sit at `dataset_version="0.2.0"`; `model_input_advancement` and `model_input_observation_batted_ball` are at `0.3.0`; `model_input_geometry` is at `0.4.0` (the latter two carry the `propensity_p_observed` / `propensity_artifact_id` columns).
- `datasets.py` / `eda.py` — Phase-2 snapshot + EDA producers.
- `model_config.py` / `publication.py` — Phase-2 publication gate.
- `model_configs/` — one `ModelConfig` JSON per registered Bayes target (12 today: 6 obs propensity, 5 geometry, ball_handler), consumed by `bc-stats check-publication-gate`. Each pins `dataset_version` and carries `expected_blocking_findings` (EDA block-severity findings reviewed and accepted, matched by code) plus `addressed_weak_identifications` (`partial_pool` for the obs targets, `drop` for E and D). CAVEAT: `run-eda` stamps the CURRENT registry `dataset_version`, not the frozen version recorded in the dataset artifact's manifest — so config pins must track the registry version, not the manifest.
- `backtests/` — controlled backtest harnesses. `mnar_masked.py` is the MNAR design check: synthetically mask observed events with class-dependent intensity (P(masked) = w_class × per-context intensity), fit corrected (`gamma_propensity_class`) and uncorrected (`gamma_propensity_zero`) variants on the survivors, and gate on recovery of the masked slice's class mix (focal-share relative error reduction ≥ 0.25), held-out non-regression, and sampler diagnostics. Driver: `scripts/mnar_masked_backtest.py`; writes `artifacts/statistical/backtests/mnar/<run_id>/metrics.json` with `overall_pass`. The `gamma_propensity_class` arm is the negative control (the learned coefficient learns the survivor tilt; it does not correct MNAR). The harness also evaluates an `offset` arm: a pure post-hoc reweight of the `gamma_propensity_zero` arm's exported per-event class shares by the ORACLE per-class offset `delta_c = logit(clip(w_class[c] · mean(intensity_tiers), eps, max))` (the Task-1 scoring-time mechanism applied to known mask probabilities). The `offset` block in `metrics.json` carries `focal_share_error` (offset vs uncorrected), `relative_reduction`, `tv`, and `pass`; held-out / diagnostics are inherited from the noprop fit (the reweight only touches the masked-slice imputation). Helpers: `oracle_selection_offset`, `reweight_class_shares_per_event`, `evaluate_offset_arm`.
- `calibration.py` — temperature scaling, isotonic regression, ECE, Brier, reliability curves. Numerical primitives consumed by `bayes/training.py`.
- `sensitivity.py` — MNAR pattern-mixture sensitivity ribbon for the imputation softmax exports. `marginal_shares(export, offset)` event-averages the per-event `shares_c·exp(delta_c)` renormalization (the Task-1 offset mechanism as a post-hoc reweight, no refit); `sensitivity_ribbon(export, dimension)` sweeps each class's selection log-odds over `DEFAULT_GRID` (`±{0.25,0.5,1.0}` nats) and returns the per-class marginal band (`delta=0` reproduces the published MAR marginal); `ribbon_band` collapses to `[low, high]`; `offset_recovers_target` is the TV-to-target check used by the backtest validation. Driver `scripts/sensitivity_ribbon.py` writes `exports/sensitivity_ribbon.parquet` beside each published `geometry_*` fit and `--validate-backtest <run>` confirms the grid spans the masked backtest's oracle correction. Design + validation: `notes/data-coverage-implementation/mnar-selection-offset-design.md`.
- `validate.py` — cross-phase `validate_artifact()` dispatcher. Reads `manifest.kind` and runs the appropriate check suite. Emits a `ValidationReport`.
- `manifests.py` — artifact-id generation, atomic manifest read / write, published-pointer resolution rooted at `BC_STATS_PUBLISHED_ROOT` (per-branch) with a global fallback under `artifacts/statistical/published/`.
- `schemas.py` — Pydantic v2 schemas for manifests, datasets, diagnostics, validation, EDA report, validation report.
- `splits.py` — `game_hash_fold(game_id, fold_count)` BLAKE2s splits.
- `leakage.py` — split-registry leakage detection.
- `outputs.py` / `diagnostics.py` — Phase-4/5 hooks (mostly stubs).
- `bayes/` — Phase-4 hierarchical-Bayes runtime. `artifacts.py` lays out `artifacts/statistical/bayes/<model_name>/<artifact_id>/{inference,exports,validation,manifest.json}`. `training.py` exposes `run_bayes_model(...)` which looks up the named target in the registry, builds event-grain inputs via `spec.prep_fn`, samples prior predictive, NUTS posterior (unless `prior_only`) under the configured backend (numpyro for full fits), and posterior predictive, then writes `inference/*.nc`, `exports/{posterior_summary,calibration_curve,event_propensity}.parquet` (Bernoulli targets) or `exports/{posterior_summary,event_credit}.parquet` (multinomial targets), and `validation/diagnostics.json` atomically. `training._posterior_event_means_bernoulli` handles the Bernoulli export path; `_posterior_event_softmax` + `_export_event_credit_shares` handle the multinomial path. `specs.py` defines `BayesTargetSpec` (frozen Pydantic v2): `name`, `dimension`, `dataset_name`, `dataset_dimension_filter`, `outcome_kind ∈ {"bernoulli","multinomial","count"}`, `multinomial_export ∈ {"credit","ball_handler","geometry","pitch_summary","advancement",None}` (routes the multinomial export branch — `outcome_kind` is `"multinomial"` for all of them), `count_export ∈ {"park_factor","run_expectancy",None}` (routes the count export branch; a `@model_validator` enforces `count_export` is set iff `outcome_kind == "count"`), `dl_proposal_dimension` / `dl_class_collapse_positive` / `default_flavors` (gamma_dl flavor gating; a `@model_validator` forces `default_flavors=("gamma_dl_zero",)` when `dl_proposal_dimension is None`), `prep_fn`, `builder`, `sample_size`, `published_manifest_name()`. `sample_size` is the spec-level training row budget (None means "full dataset"); `run_bayes_model`'s resolver picks the smoke-limit kwarg first, then `BC_STATS_SMOKE_LIMIT`, then the `--smoke` default, then `spec.sample_size`. `registry.py` exposes `register_target` / `get_target` / `all_targets`. `targets/observation.py` registers six obs propensity targets — `trajectory_observedness`, `location_side_observedness`, `location_depth_observedness`, `location_edge_observedness`, `general_location_observedness`, `ball_handler_position_observedness`, all with `outcome_kind="bernoulli"`, `sample_size=10_000` (sample-size sweep showed OOS AUC plateau by 10K; 100K only buys +0.016 PR-AUC at 10× wall-clock — see [[phase4-obs-propensity-findings]]). `pulled_opposite` is excluded — purely derived, 0% observed. `targets/credit.py` registers `putout_credit_allocation` + `assist_credit_allocation` (both `multinomial_export="credit"`), `sample_size=10_000`. `targets/ball_handler.py` registers `ball_handler_imputation` (`outcome_kind="multinomial"`, `multinomial_export="ball_handler"`, `sample_size=10_000`) — Model D, sharing the obs dataset + `dataset_dimension_filter="ball_handler_position"` with Model A's `ball_handler_position_observedness` Bernoulli but distinct in `name` / `outcome_kind` / `prep_fn` / `builder` (the registry keys on `name`). `manifest_ingest.py::aggregate_observation_propensity_frames` feeds the `scorer_observation_propensities` SQLMesh `@model`; `aggregate_fielding_credit_frames` (schema `CREDIT_SHARE_SCHEMA`, scoped to `multinomial_export=="credit"`) feeds `imputed_fielding_credit`; `aggregate_ball_handler_frames` (schema `BALL_HANDLER_SCHEMA`, scoped to `multinomial_export=="ball_handler"`) feeds `imputed_ball_handler_probabilities`; `aggregate_geometry_frames` (`GEOMETRY_SCHEMA`, `multinomial_export=="geometry"`) feeds `imputed_batted_ball_geometry`; `aggregate_advancement_frames` (`ADVANCEMENT_SCHEMA`, `multinomial_export=="advancement"`) feeds `imputed_advancement_probabilities`; `aggregate_park_factor_frames` (`PARK_FACTOR_SUMMARY_SCHEMA`, `count_export=="park_factor"`, reads each artifact's `exports/park_factor_summary.parquet`) feeds `park_factor_summary`; `aggregate_run_expectancy_frames` (`RUN_EXPECTANCY_SUMMARY_SCHEMA`, `count_export=="run_expectancy"`) feeds `run_expectancy_summary`; `aggregate_pitch_summary_frames` (`PITCH_SUMMARY_SUMMARY_SCHEMA`, `multinomial_export=="pitch_summary"`) feeds `pitch_summary_distribution`. Every helper always yields at least one (possibly empty) typed frame so the `@model` schema persists before any artifact publishes.
- `models/credit.py` — event-grain PyMC builder `build_fielding_credit_model(inputs, *, priors)` for dual-arm fielding-credit allocation. Per-event softmax `π_{e,k} = softmax(η_{e,k})` over the personnel-eligible position set; per-position `alpha_position` (`ZeroSumNormal` over `position`) plus per-FE × position `delta_<fe>` (`ZeroSumNormal` over position with dims `(<fe>_levels, position)`). No scalar-per-event terms: season / scorer / park / source REs and per-event global FEs would enter every position logit equally and cancel exactly inside the per-event softmax (in both likelihood arms), so the builder omits them. Two likelihoods share `π`:
  - Supervised: `pm.Multinomial("Y_supervised", n=U_sup, p=π[Y_supervised_event_idx], observed=counts)` on unmasked well-attributed events. Load-bearing — provides the per-event signal an aggregate-only arm lacks.
  - Aggregate: `T_target[m] ~ Normal(Σ U_e * π_{e,k}, sigma_box_aggregate)` on the masked subset, at grain `(game_id, fielding_team_id, player_id, fielding_position)`. `T_target` is the deterministic sum of *hidden* `known_credit` over the masked events at that cell (we control the mask, so no authority-source split — single `sigma_box_aggregate`).
  Neither `π` nor `T_pred` is registered as a `pm.Deterministic` (would write 10k × 9 × 4000 × 8 B ≈ 2.9 GB into `posterior.nc` at `sample_size=10_000`). `_posterior_event_softmax` reconstructs `π` analytically from the parameter posteriors. One runtime knob gates fit behavior: `BC_CREDIT_MIN_NATURAL_UNK_RATE=<float>` filters seasons whose per-PBP-source natural-unknown rate falls below the threshold from `_CACHED_NATURAL_UNKNOWN_RATES` — modern 1972+ PBP is essentially 0% natural unknown and contributes no inference scope. (`BC_CREDIT_NONCENTER_SEASON` is gone — it parameterized the per-event `beta_season` RE, which was removed along with the other canceling scalar-per-event terms.) The shipped operating point is `full-10k-v15-tuned` (1% rate floor). The shipped fit lands held-out top-1 ≈ 0.529, TV ≈ 0.01, max per-position abs dev ≈ 0.006 — see `notes/data-coverage-implementation/03-hierarchical-models.md` for the full table and the retraction note on the abandoned `direct_handler_position` lever.
- `models/_credit_data.py` — prep for the dual-arm credit model. `FIXED_EFFECT_COLUMNS = (result_family, base_state_start, outs_start, frame_start, alignment_regime)` — every FE must be populated on more than `PRODUCTION_FE_COVERAGE_FLOOR` (1%) of the production inference target (events with `unknown_credit_need > 0 AND personnel_hard_mask_available AND eligible_for_allocation`); `_assert_fixed_effects_cover_production_slice` runs at the top of `prepare_event_credit_inputs` and raises if any FE falls below the floor. `prepare_event_credit_inputs` filters to well-attributed events (`known_credit > 0 AND personnel_hard_mask_available`), deterministically holds out 10% of GAMES via `game_hash_fold(g, fold_count=10) == 0` for OOS scoring, subsamples the remainder game-level, applies `_apply_synthetic_mask` (per-event Bernoulli ∝ per-position weight × per-(season, source_family) intensity, with a per-game floor of one unmasked event), and emits `EventCreditInputs` with `is_masked`, `Y_supervised_*` arrays (supervised arm), aggregate-arm indicator triples computed from the masked subset's known_credit, and a `HeldOutSet` (true_position + design covariates) for OOS. `REAL_UNKNOWN_RATES_BY_POSITION` (P 1.8%, C 6.9%, 1B 42.2%, 2B 9.0%, 3B 4.3%, SS 7.8%, LF 9.1%, CF 11.1%, RF 7.9%) and `_CACHED_NATURAL_UNKNOWN_RATES` (per-season PBP) are module constants derived once from the upstream authority cache and committed; re-computing requires re-deriving from `credit_authority_targets.parquet`. Aggregate-arm targets are computed from the masked subset's hidden Y rather than the box residual — there is no `materialize_credit_authority_targets` cache. `MIN_EVENTS_PER_SEASON=50` row floor. Multinomial posterior export chunks at `POSTERIOR_CREDIT_CHUNK_DEFAULT=5_000` events at a time (vs `250_000` for Bernoulli) because the `(chain, draw, n_chunk, K=9)` reconstruction array is 9× wider per event.
- `models/observation.py` — event-grain PyMC builder `build_observation_model(inputs, *, priors)`. Linear predictor: alpha + centered random intercept on season (data-dense — ~860 rows/cell at 100k subsample drives a funnel-flip under non-centered) + non-centered random intercepts on scorer / park (and source_family when `len(coords["source"]) > 1`); integer-indexer fixed effects per categorical covariate (`game_type`, `frame_start`, `exposure_status`, `league`, `result_family`, `pa_result`, `leverage_bucket`, `batter_hand`, `pitcher_hand`, `personnel_confidence`, `context_confidence`) drawn from `pm.ZeroSumNormal` over the full level coord (sum-to-zero identification); per-continuous standardized slopes on `outs_start`, `inning_start`, `score_margin`, `leverage_index`, `runs_on_play`, plus paired `is_missing` indicators when any rows were imputed. Likelihood uses `pm.Bernoulli(... logit_p=eta, ...)` directly — no `p_observed` Deterministic in the model graph (would have been 12M events × 4000 draws × 8 B ≈ 380 GB at full scale). No DL covariate. No `event` coord on the model — PyMC infers the event dim from the data length, posterior parameter arrays stay coord-named (`season`, `scorer`, `park`, `<cat>_levels`).
- `models/_event_data.py` — `EventObservationInputs` (frozen Pydantic v2) carrying y, event_keys, random-effect indexers, per-fixed-effect `FixedEffectDesign` (`codes` integer array + `levels` / `reference_level` / `non_reference_levels`; reference is `levels[0]`, non-reference is `levels[1:]`), per-continuous `ContinuousFeature` (standardized + missing indicator + raw_mean/raw_std), and the coord dict. `prepare_event_observation_inputs(parquet_path, *, dimension, smoke_limit, seed)` reads the modeling dataset (which already inner-joins `event_observation_context`), asserts indexer contiguity, and emits the inputs.
- `pymc_utils.py` — `SamplingConfig` + `SMOKE_CONFIG`/`DEFAULT_CONFIG` + `sample_model`/`prior_predictive`/`posterior_predictive`. `SamplingConfig.backend` selects the NUTS sampler. `DEFAULT_CONFIG` uses `backend="nutpie"` (the project default for full fits); `SMOKE_CONFIG` stays `backend="numpyro"`. Both compile the event-grain model with thousands of scorer / park coords in seconds; stock PyMC takes minutes. `BC_STATS_BAYES_BACKEND` overrides per fit. `DEFAULT_CONFIG` ships `target_accept=0.95`, `max_treedepth=12`; `SMOKE_CONFIG` keeps 50 draws × 50 tune × 2 chains. Imports PyMC and ArviZ at module top; the module is itself lazy-imported by the CLI handler.

### Bayes smoke loop

- `just fit-bayes <model> <dataset-artifact-id> <fit-artifact-id> --smoke` runs `SMOKE_CONFIG` (50 draws × 50 tune × 2 chains, stock PyMC backend) and applies the default 100k-row subsample. `--prior-only` short-circuits before `pm.sample`. Subsampling uses `df.sample(n=N, seed=20260513)` for reproducibility.
- `BC_STATS_SMOKE_LIMIT=N` overrides the row count (mirrors `BC_PRETRAIN_DATASET_LIMIT`).
- `BC_STATS_BAYES_DRAWS` / `BC_STATS_BAYES_TUNE` override `DEFAULT_CONFIG`'s draws / tune (default 1000 / 1000); `_resolve_sampler_config` in `training.py` reads them alongside `BC_STATS_BAYES_BACKEND`, returning the base config untouched when none are set and otherwise rebuilding `SamplingConfig` with the overrides (chains / target_accept / max_treedepth stay at the base). They exist for the case where a model's `alpha_class` intercept ridge slow-mixes under the default and needs longer sampling to clear the default `rhat ≤ 1.05` / `ess ≥ 100` gate.
- `validate-artifact <id> [--model <name>]` dispatches on `manifest.kind == "bayes"` to thresholds in `validate._validate_bayes`: smoke gates (`rhat_max ≤ 1.5`, `ess_bulk_min ≥ 3`, `divergences ≤ 5% of total_draws`, ECE/bucket-dev warn-level only) vs default gates (`rhat ≤ 1.05`, `ess ≥ 100`, zero divergences). The macOS multiprocess-fork-after-Accelerate hang only matters for the PyMC backend; the numpyro backend uses JAX vectorized chains and ignores `cores`. `--model` is required when multiple registered models share an artifact id (all six obs propensity targets use `10k-v1`); without it the validator errors `artifact_id=... is ambiguous`. The default ess gate is 100 (not 400) because the obs propensity design's rare-class FE blocks (`__unknown__` in 3-level cols, NNL/ECL/NN1/NN2 in 8-level `league`) slow-mix as a sampler-efficiency artifact at any N — see [[phase4-obs-propensity-findings]].

### Event propensity export

- `exports/event_propensity.parquet` ships per fit, schema `(event_key: int64, dimension: utf8, p_observed_mean: float64)`. Computed by `_posterior_event_means`: reconstructs `η_e` per event from the posterior parameter draws (alpha + beta_season[s(e)] + beta_scorer[r(e)] + beta_park[p(e)] + delta_full[c(e)] + Σ γ_j x_j(e) + Σ δ_missing_j is_missing_j(e)), sigmoids, and reduces over `(chain, draw)` — one `(chain, draw, chunk_size)` slab at a time. Default chunk 50k. Memory per chunk at full DEFAULT_CONFIG: `4 × 1000 × 50k × 8 B = 1.6 GB` per slab (plus same-size temporaries); the full-coverage export scores ~8–12M events per dimension, so the 250k chunk that predated full-coverage scoring swapped the machine when two scoring jobs overlapped. Smoke fits also score the full dimension (the export is the point of the fit, and the 100-draw smoke posterior makes it ~50 s per 10M events); iterate on synthetic or subsampled datasets when you need a seconds-scale loop. At 12M events × 8 bytes the parquet itself is ~96 MB. The Bernoulli likelihood uses `logit_p=eta` so no per-event posterior tensor is materialized in the model graph.
- No `posterior_predictive.nc` is written: `E[y_rep | data]` is `E[sigmoid(η_e) | data]` analytically for a Bernoulli, so the bucket-deviation calibration check uses `p_mean` directly.
- The published operating point for all six obs propensity targets is `10k-v4-fullscore`: each export covers every event of its dimension in saturated seasons (`ball_handler_position` covers 100% of events; the geometry dims exclude only unsaturated seasons). Held-out ROC-AUC 0.898–0.973 / PR-AUC 0.909–0.992 vs prior baselines 0.374–0.892.
- The `scorer_observation_propensities` SQLMesh `@model` is a thin gather over published `event_propensity.parquet` artifacts: grain `(event_key, dimension)`, columns `(event_key, dimension, p_observed_mean)` plus the eight estimated-metadata contract columns. Materializes a typed empty frame until at least one per-dim Bayes pointer lands.

### Event credit export (multinomial targets)

- `exports/event_credit.parquet` ships per multinomial fit, schema `(event_key: int64, fielding_position: int8, credit_type: utf8, expected_share: float64, none_share: float64?)`. `_posterior_event_softmax` reconstructs per-event `η_{e,k}` from posterior parameters (alpha_position[pos] + Σ delta_<fe>[c_e, pos] across active FEs), softmaxes over the position set, and reduces over `(chain, draw)`. `_export_event_credit_shares` writes the long-form table at the `(event_key, fielding_position, credit_type)` grain. For the putout target the export covers BOTH the supervised and masked subsets of the training set (complete over the training grain). For the assist target the shipped export is the 463,093-event production slice (`credit_type='putout' AND unknown_credit_need > 0 AND personnel_hard_mask_available AND eligible_for_allocation`), not the training grain — 4,167,837 rows (463,093 × 9 positions), built by `build_production_scoring_frame` and scored with `_posterior_event_softmax_putout_marginalized` over the published v1.5 putout posterior (`putout_position` is unknown on the production slice). Each event's 9 position shares + `none_share` sum to exactly 1.
- For K=10 fits (assist with a NONE sentinel as position 10), only positions 1..9 are emitted as rows; the per-event `none_share = π_{e,10}` rides along on every position row so downstream consumers can compute `P(any credit) = 1 - none_share` without re-joining the artifact. For K=9 fits (putout), `none_share` is NULL.
- `validation/held_out_metrics.json` ships per credit-allocation fit. Top-1 / top-3 accuracy, log-loss, per-position PR-AUC (1B is near-trivial; OF positions discriminate harder), macro PR-AUC, and the per-position-prior baseline. K=10 fits add an `any_assist` block with `pr_auc` (binary NONE vs ¬NONE) and a `baseline_pr_auc` equal to the empirical ¬NONE rate. Held-out games are the 10% at `game_hash_fold(g, fold_count=10) == 0` and are never seen during training. Use these to pick the operating point on N-sweeps. For the assist target the held-out metrics are putout-marginalized (production-faithful): `putout_position` is observed on held-out events but unknown on the production target, so `_evaluate_held_out` marginalizes over the published v1.5 putout posterior, records a `putout_marginalized: true` flag, and excludes `putout_position` from slice calibration when marginalizing. It also records an `observed_putout_upper_bound` block (metrics conditioned on the true putout) — an upper bound only, not the production metric. **Caveat on held-out PR-AUC.** Per-event FEs that correlate with attribution availability (handler-known events get clean attribution; handler-unknown events are exactly the inference target) inflate held-out PR-AUC without giving production benefit. The 1% production-coverage guard on `FIXED_EFFECT_COLUMNS` is the front-line defense; for any new FE candidate also evaluate the held-out lift restricted to the slice where that FE is NULL.

### Model C credit allocation

`bayes/targets/credit.py` registers two specs sharing the dual-arm builder and prep function:

- `putout_credit_allocation` — K=9 softmax. The v1.5 operating point. Truth is the per-event `known_credit` grid (always sums to 1 for the well-attributed training slice).
- `assist_credit_allocation` — K=10 softmax with a NONE sentinel as the 10th class. v3 cut 1 — single-assist events only. Truth is one-hot at the assist position when `A_count==1`, one-hot at NONE when `A_count==0`. Multi-assist events (force-DPs, rundowns) are filtered upstream. The prep step also joins per-event `putout_position` (1..9) from the same dataset's putout `known_credit` rows and exposes it as an FE; `delta_putout_position` of shape (9, 10) gets fit like every other FE × position interaction. At inference time the published v1.5 putout posterior is marginalized over by `_posterior_event_softmax_putout_marginalized`, which is wired into BOTH the production-slice export and the held-out eval. (The training-set export still uses observed `putout_position`, but the shipped export is the 463,093-event production slice, not the training grain — `putout_position` is unknown there.) Coverage guard for assists filters on `credit_type='putout' AND unknown_credit_need > 0` (assist rows always have `unknown_credit_need=0` upstream); `putout_position` is excluded from the standard per-event check (structurally NULL on the production slice) and instead checked per-level on the training set so each j ∈ {1..9} has at least the 1% floor of representation.
- Multi-assist count submodel SHIPPED as the separate `assist_count` target (v3.1) — see Model C assist count below. Errors (v4) are DATA-BLOCKED: `error_credit` (`models/error_credit.py`) is code-complete but every error row has `unknown_credit_need=0` (no upstream missing-error signal), so there is no production imputation target — the model only yields held-out diagnostics on fully-attributed events, not a coverage surface. The DP state-gating arm is unbuilt. Team-residual fallback to v5; player REs still deferred.

### Model D ball-handler imputation

`bayes/targets/ball_handler.py` registers `ball_handler_imputation` — a single-arm K=9 categorical softmax over the fielder position that handled a batted ball, for events whose handler is unobserved. A trimmed `build_fielding_credit_model`: keeps the supervised softmax arm, drops the aggregate-box Normal arm, the synthetic mask, and the park/source REs. Cut-1 sets γ_dl=0 and γ_credit=0. Carries the same per-class `gamma_propensity` hook as Model E (`ZeroSumNormal` over the position axis on the standardized propensity logit; default flavor `gamma_propensity_zero` — see Model E for why). The published operating point is `d-noprop-10k` (gamma_propensity_zero): held-out top-1 0.2170 vs prior-baseline 0.1709.

- `models/_ball_handler_data.py` — `prepare_ball_handler_inputs` reads the obs dataset `model_input_observation_batted_ball`, filters to `dimension='ball_handler_position' AND observed_status='observed' AND training_weight>0`, casts `raw_value`→int 1..9, builds one-hot `counts` `(n_event, 9)`, a composite `season_league` index, a `scorer` index, and FE designs for `result_family` / `base_state_start` / `outs_start` / `alignment_regime`. Holds out 10% of games (`game_hash_fold(g, fold_count=10)==0`), game-level cumulative-budget smoke subsample, and a `MIN_EVENTS_PER_SEASON=50` floor applied per **season-league cell** (not per season — the cell is the RE coord). `_assert_fixed_effects_cover_production_slice` runs the 1% FE-coverage guard on the handler-**unobserved** slice (`observed_status != 'observed'`). Reuses `FixedEffectDesign` / `HeldOutSet` / `ProductionScoringFrame` from `_credit_data.py` so the `training` reconstruction + held-out eval helpers accept `BallHandlerInputs` unchanged (its `HeldOutSet` populates all five idx fields + `true_position`; `credit_type="ball_handler"` keeps `_evaluate_held_out` on the non-marginalized path). `build_ball_handler_production_frame` returns a `ProductionScoringFrame` over the handler-unobserved slice, FE-encoded against the training vocab (unseen levels → `-1`).
- `models/ball_handler.py` — `build_ball_handler_model`. `η_{i,k} = α_pos_k + Σ_fe δ_fe[c_i,k]`; `α_pos` + per-FE `δ_fe` are `pm.ZeroSumNormal` over the position axis. DEFERRED: `_posterior_event_softmax` in `bayes/training.py` does not yet reconstruct the `gamma_handler` term, so the production export path must be taught it before a production geometry fit with the handler covariate active can publish. Likelihood `pm.Multinomial("G_observed", n=1, p=softmax(eta))`; no `π`/`η` Deterministic, `_posterior_event_softmax` reconstructs `π` from `alpha_class` + FE deltas (+ active gamma terms).

### Model F park factors

`bayes/targets/park_factor.py` registers `park_factor_runs` — the first `outcome_kind="count"` target (`count_export="park_factor"`, `sample_size=500_000`). - `models/park_factor.py::build_park_factor_model` — `team_runs ~ NB(mu=lambda, alpha=phi)` with `log lambda = log(exposure_pa) + alpha_season_league + offense[team-season] + pitching[opp-team-season] + theta_park[park-season-league] + home_adv·is_home`. `theta_park` is the only coord-sized Deterministic — the published park factor (`park_factor_mean = exp(theta_mean)`). KEY identification fix: `theta_park` is the raw per-cell park effect **centered to sum to zero WITHIN each (season, league) group** (`_center_within_group`, a constant one-hot membership matmul — JAX-safe, no scatter-add), not globally across all park-season-league cells; this stops era scoring from leaking into the park effect when `alpha_season_league` under-absorbs. The raw effect optionally follows an **AR(1) persistence prior across consecutive seasons within a (park, league) chain**: `pm.AR("ar_park", rho=[0, rho_park], sigma=sigma_park_innov, init_dist=Normal(0, sigma_park_init), constant=True, dims=(ar_chain, ar_step))` over a padded `(n_ar_chains, n_ar_steps)` grid, gathered to cells by `(ar_chain_idx, ar_step_idx)`. `rho_park ~ Beta(2,1)`. `pm.AR` is used (not `pytensor.scan`) because a scan whose sequence traces to an RV trips PyMC's prior-predictive RNG-update collection. Offense / pitching are non-centered per-(team, season) random effects. No team-game-sized Deterministic (no `lambda`). Two builder gates mirror `run_values::_era_regime_enabled`: `BC_PARK_FACTOR_DISABLE_AR1` (off → independent `z_theta_park × sigma_park` raw effect, still season-league-centered) and `BC_PARK_FACTOR_DISABLE_HOME_ADV` (off → drop the HFA term). The HFA term + the `home_idx` road/home split are the sensitivity diagnostic for the home-park/home-team confound.
- `models/_park_factor_data.py` — `prepare_park_factor_inputs` aggregates per-event `model_input_park_factors` to one row per `(game_id, batting_team_id)` with summed `runs_on_play` and `plate_appearances` exposure. Carries `home_idx` (batting team is home), `cell_season_league_idx` (cell → season-league group, for centering), and `ar_chain_idx` / `ar_step_idx` / `n_ar_chains` / `n_ar_steps` (the AR(1) padded grid keyed by (park, league) chain and season rank). `MIN_GAMES_PER_PARK_CELL=25` floor drops unidentified park cells; 10% game holdout ships for OOS, levels unseen in training encode to `-1`. DEFERRED — `park_episode_status` is 100% NULL in the dataset, so no `park_episode_id` is derivable to reset the AR(1) chain at structural park changes; the AR(1) keys on (park, league) only. Umpire / weather / surface / day_night spec covariates are DEFERRED — none of those columns exist in `model_input_park_factors` (no umpire id, no weather/temp/wind, no surface, no day_night). Batter/pitcher hand exist per-event but the prep is team-game grain (hand varies within a team-game row), so hand FEs are DEFERRED to an event-grain restructure.
- Export: `_export_park_factor_posterior` (long-form per-(cell, chain, draw) `theta_park`) + `_export_park_factor_summary` (one row per `(park_id, season, league, outcome)` with `theta_mean`/`sd`/HDI, `park_factor_mean`, `ess_bulk`, `rhat`).   **Two-stage fit.** Stage 1 trains the trunk + heads on a context-only layout (no entity IDs, no observed-outcome inputs). `scripts/pretrain_emit_offsets.py` loads the saved stage-1 `model.keras` (with `compile=False`), builds an inference submodel whose outputs are the per-head `{head}_logits` intermediate Dense layers, streams the dataset through `.predict()`, and writes one float16 parquet per head under `artifacts/statistical/deep/<stage1_spec>/<stage1_id>/offsets/<head>.parquet` with columns `event_key, logit_0 .. logit_{K-1}`. Stage 2 runs the full architecture (with batter+pitcher embedding group + observed outcomes as inputs) with `BC_PRETRAIN_OFFSET_ARTIFACT=<stage1_id>` set: `pretrain/training.run_pretrain` joins the per-head offsets onto the dataset by `event_key`, encodes `x[f"offset_{head}"] = float32 (N, num_classes)`, overrides head class labels with stage-1's manifest so cached logits align by index, and passes `offset_inputs={...}` to `build_pretrain_model`. Loss path is `CE(softmax(stage1_logits + Δ_logits), label)` so the embedding only learns the residual / interaction signal not predictable from context alone.

  **Active spec.** `targets.py` registers two spec names: `event_universe` (full layout) and `event_universe_context` (stage-1 context-only layout). Both share the 5-head spec and the batted-ball row filter. Full layout: embedding group `('player', ('batter_id', 'pitcher_id'))` plus ungrouped `park_id` / `scorer`; low_card / numeric intentionally include post-event observed outcomes (`pa_result`, `outs_on_play_capped`, `runs_on_play_capped`, `r1/r2/r3_advancement`). `validate_pre_event` is NOT called on pretrain layouts for this reason. Heads (5, all imputation targets): `trajectory_remapped`, `batted_location_general`, `batted_location_depth`, `batted_location_edge`, `batted_to_fielder_class`. Row filter: `pa_result IN (<11 batted-ball outcomes>)`.

  **Training config.** `training.py` honors split optimizers (trunk Adam 1e-3, embed Adam 5e-3→1.5e-3), Kendall-Gal uncertainty weighting, `BC_PRETRAIN_LOSS=focal` (γ via `BC_PRETRAIN_FOCAL_GAMMA`), and `BC_PRETRAIN_USE_HARD_HEAD_ES=1` with `BC_PRETRAIN_HARD_HEADS=...` (default `trajectory_remapped,batted_location_general,batted_to_fielder_class` for the active 5-head spec). Smoke knob: `BC_PRETRAIN_DATASET_LIMIT=<N>` deterministically subsamples both stages with `df.sample(n=N, seed=0)` so stage-1 / emit / stage-2 agree on rows.

  `artifacts.py` writes one embedding matrix per embedding unit (group or ungrouped col); `vocab.json` keys mirror those units. Pretrain training-time diagnostic probes (the historical `SlashLineProbe` / `FieldingProbe` / `OutfieldArmProbe` / `LinearProbeDownstreamCallback` / `MonteCarloSlashProbe`) were removed when the pretrain head set dropped `pa_result`. Replacement evaluation: batted-ball perm-imp regression suite (`scripts/permutation_importance_generic.py`).

- `leakage_probes.py` — `source_probe_held_out(embeddings, source_labels, held_out_family)` → `ProbeResult` with sklearn LR + AUC tiers (`>=0.75` → diagnostic_only / `<0.65` → full / `[0.65, 0.75)` → manual_review). Also `oof_integrity_probe(probabilities, game_ids, fold_count=...)` → `OofIntegrityResult`: post-hoc check that every exported OOF row's `fold_id` matches `splits.game_hash_fold(game_id)`, ≥2 distinct folds are present, and no grain value spans partitions; artifacts without a `fold_id` column come back `unverifiable`.

- `targets/` — per-target registrations.
  - `geometry.py` — 4 specs (trajectory, location_side, location_depth, location_edge). Pre-event layout: high-card batter / pitcher / park / scorer; numeric ball/strike count, outs_start, score_margin, leverage_index, season, inning_start.
  - `advancement.py` — 3 specs (`advancement_r1/_r2/_r3`), 7-class each, per-baserunner filter. Pre-event layout includes `runner_id` in high-card and `baserunner` / `base_start` in low-card / numeric. Excludes the dataset's own `trajectory_class` / `location_depth_class` / `ball_handler_position_class` / `hit_or_out` / `runs_on_play` / `result_family` (all post-event leak). Not registered on import; the `model_input_advancement` SQL gap closes before `_register()` runs.

  Each target's `_register()` invokes `validate_pre_event(layout)`. Every registered spec MUST set `pretrained_embeddings_artifact_id = "event_universe"`. `_maybe_load_pretrained_embeddings` early-returns on `None` and `BC_DEEP_PRETRAIN_ARTIFACT_OVERRIDE` never fires in that case. `test_every_geometry_spec_declares_pretrain_artifact` guards geometry; add equivalent for new target modules. Override via `BC_DEEP_PRETRAIN_ARTIFACT_OVERRIDE=<spec_name>` when running against a non-canonical pretrain.

  Fielding-credit DL allocation is out of scope. Spatial-allocation task that doesn't benefit from shared player embeddings; Phase-4 Bayes owns it. The `batted_to_fielder_class` pretrain head stays as auxiliary signal for the location heads. Pitch-summary DL imputation (`has_count`, `has_pitch_sequence`, per-stream dims) is also Phase-4+; deferred specs are not currently in tree.

### Pretrain invariants

- **Pre-event inputs only on downstream supplements.** Every supplement's `FeatureLayout` must contain only features observable at inference time. Post-event columns (`fielder_chain`, `pa_result`, `result_family`, `batted_to_fielder*`, `outs_on_play`, `runs_on_play`, `*_end`, cumulative AB pitch/swing counters, `gap_class`, `fielding_evidence_status`, `hit_or_out`) train to a distribution that does not exist at scoring time and let the model shortcut entity priors. `validate_pre_event` enforces a deny-list and is called from every supplement's `_register()`. The pretrain layout is exempt. See [[pretrain-architecture]].
- **Time-forward gate eval.** Permutation-importance and acceptance gates run on `time_forward_fold = 'VALIDATE'` (season = 2023). Use `scripts/permutation_importance_generic.py --time-forward`. The training split stays on `primary_fold` (HASH(game_id)) to maximize data.
- **Pretrain head set.** Heads cover only imputation targets (data genuinely missing in retrosheet). Fully-observed outcomes go in the input set, not the head set. See [[pretrain-architecture]] for the rationale and current head list.
- **Pretrain → supplement gate.** No-pretrain baseline ran per supplement on the stripped layout sets the gate floor; pretrained artifact must hit ≥ ×1.5 batter-side Δ_CE and not regress on park / pitcher. Recorded under `notes/data-coverage-implementation/phase3-acceptance-gates-v6.md` (filename label is incidental).
- **Training labels = directly recorded only.** Modeling-dataset SQL (`model_input_geometry`, `model_input_event_universe`, `model_input_advancement`) uses `observed_status = 'observed'` (not `IN ('observed', 'derived')`) and `class = raw_value` (not `COALESCE(raw_value, deduced_value)`). Heuristic deductions in `calc_batted_ball_type` (HR→Fly, OF-putout→AirBall, infielder-assisted-putout→GroundBall, fielder-position-derived location_side/depth) and `event_observation_geometry` still surface for analyses / published aggregates; they are excluded from the DL training-label path so pretrain heads + downstream supplements train only on what was directly recorded. The `pulled_opposite` dimension is purely derived (zero eligible rows under this rule).
- **Downstream embed-dim env.** Geometry fits need `BC_DEEP_FORCE_EMBED_DIM=128` to match the pretrain's capped 128-D player embedding. Combine with `BC_PRETRAIN_SKIP_DIM_MISMATCH=1` so the ungrouped `park_id` (pretrain dim 17) and `scorer` (pretrain dim 95) layers skip warm-start instead of failing. Tracked as a follow-up in `notes/followups.md`.

## SQLMesh @models (in `bc/models/intermediate/coverage/`)

- `dl_credit_proposal_manifest.py` — grain `(event_key, player_id, fielding_position, credit_type)`, joined by `model_input_fielding_credit`. Materializes as a zero-row stub (fielding-credit DL out of scope).

- `imputed_fielding_credit.py` — grain `(event_key, player_id, fielding_position, credit_type)`. Streams each published Bayes credit target's `exports/event_credit.parquet`, joins `personnel_fielding_states` via `event_personnel_lookup` inside `execute()` to attach `player_id` per `(event_key, fielding_position)`, and stamps the estimated-metadata contract. Zero-row typed frame until at least one credit-allocation artifact publishes.

Streams each published Bayes ball-handler target's `exports/ball_handler_probabilities.parquet` via `aggregate_ball_handler_frames`, joins `personnel_fielding_states` the same way to attach `player_id`, and stamps the estimated-metadata contract. ### Publication tiers + estimated-metadata contract

- `publication_tiers.py` — `PublicationTier` enum (`official` / `deterministic` / `estimated` / `synthetic` / `withheld`) and `PUBLICATION_TIERS: dict[str, PublicationTier]` mapping unqualified published `main_models.*` names to tiers. The twelve data-coverage coverage tables are `estimated`; the three legacy point surfaces (`linear_weights`, `park_factors`, `run_expectancy_matrix`) are `deterministic`. `tier_for(name)` accepts qualified or unqualified names; `estimated_model_names()` returns the twelve. The registry is the declared tier source; the contract stamp (`manifest_ingest`) and the `estimated_contract_complete` audit currently enforce the contract directly — deriving their target sets from the registry is a tracked follow-up.
- `manifest_ingest.stamp_estimated_contract(frame, manifest, *, method, observed_status="estimated")` stamps the eight contract columns onto every estimated frame: `artifact_id` (= `manifest.artifact_id`, replaces the old `bayes_artifact_id`), `model_name` / `model_version` / `weak_identification_flag` (from `manifest.bayes_extras`), `source_snapshot_id` (top-level manifest), `method` (per-family: `hierarchical_bayes_softmax` for multinomial shares, `hierarchical_bayes_nb` for the count/distribution summaries, `hierarchical_logistic` for the Bernoulli propensity/coverage targets), `observed_status` (constant `estimated`), `confidence_status` (= `manifest.validation_status`). `ESTIMATED_CONTRACT_SCHEMA` is the shared `{col: pl.DataType}` fragment spread into every `*_SCHEMA`. The diagnostic `ess_bulk` / `rhat` columns no longer ride the published estimated tier (run-expectancy / pitch-summary builders drop them; park already did) — diagnostics live under `validation/`.
- `BayesArtifactExtras.weak_identification_flag: bool` is the publication-gate flag the stamp reads. `run_bayes_model` populates it live at fit time from the run's diagnostics via `validate.diagnostics_indicate_weak_identification` — True when the fit is convergent-but-weakly-identified: minimum group-level `ess_bulk` below `weak_identification_thresholds()` (a config-driven multiple of the convergence gate's ESS floor: `_WEAK_IDENTIFICATION_ESS_BULK_MULTIPLIER=4×`, i.e. 400 default / 12 smoke), `rhat_max` above the half-margin comfort band (`_WEAK_IDENTIFICATION_RHAT_MARGIN_FRACTION=0.5`, i.e. 1.025 default), any divergences, or non-finite diagnostics (fail-safe). Thresholds derive from `validate._BAYES_THRESHOLDS_{DEFAULT,SMOKE}`, not parallel constants.
- Audit `bc/audits/estimated_contract_complete.sql` is wired onto all twelve estimated `@model`s: a typed-empty table passes (no rows), a populated one must carry all eight contract columns non-null.

## Manifest path discovery

`manifests.find_published_manifest(name)` resolves a model name to its published-pointer path. Resolution order:

1. `BC_STATS_PUBLISHED_ROOT` (per-branch root). Set by the justfile recipes to `artifacts/statistical/published-<branch_slug>/`.
2. `BC_STATS_GLOBAL_PUBLISHED_ROOT` (cross-branch fallback), default `artifacts/statistical/published/`. Both env vars resolve through `config.resolve_published_roots()` (the global one via `resolve_global_published_root()`); the defaults keep production behavior unchanged.

`find_published_pretrain(name)` mirrors this but resolves under the `pretrain/` subdir of each root.

Tests use `monkeypatch.setenv(cfg.ENV_PUBLISHED_ROOT, ...)` to redirect the branch root to a tmp path. `bc/tests/statistical/conftest.py` carries an autouse fixture that also redirects the global root (`ENV_GLOBAL_PUBLISHED_ROOT`) to an empty tmp dir for every statistical test, so no test resolves the machine's real `artifacts/statistical/published/` pointers — the suite is hermetic and order-independent. `cfg.DEEP_ROOT` / `cfg.BAYES_ROOT` are referenced via attribute access in `validate.py` and CLI handlers so `monkeypatch.setattr(cfg, "DEEP_ROOT", tmp_path)` propagates at call time.

## Tests

Under `bc/tests/statistical/` (CLI, prepare-dataset, run-eda, publication gate) and `bc/tests/statistical/deep/` (deep package). The fold runner test is marked `@pytest.mark.slow` because it imports Keras + Torch.

`pytest -m "not slow"` is the default fast tier. `pytest -m slow` runs the fold-runner tests. Full `pytest bc/tests` runs everything. CI scopes via these markers.

## Conventions

- Pydantic v2 `BaseModel` for any schema with validation or serialization.
- `logging.getLogger(__name__)` with module-level `_log = ...`.
- No `print()` in library code. The CLI's structured-log info messages are the audit trail.
- Atomic writes via `tempfile.mkstemp` + `os.replace` for any file the publication gate reads.
- Lazy `import keras` and `import sklearn` inside function bodies so `bc-stats --help` does not pay the cost.
