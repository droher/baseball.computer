# statistical/ — data-coverage statistical pipeline

Current policy: [modeling evidence contract](../../../docs/modeling-evidence-contract.md). Its gate-v3 and publication requirements supersede older operating-point and gate descriptions below. Default publication requires numerical, predictive, calibration, and content-bound provenance passes; `--exploratory-reason` records an explicitly exploratory research pointer and preserves failed validation. Smoke fits remain unpublishable. The pointer sweep resolves exact manifest paths, including deep aliases; `--write` additionally binds dependency evidence and can be stricter than the quick read-only sweep. `--json-output` exposes all six evidence dimensions. Run-expectancy mean coverage is a studentized diagnostic, not fitted-likelihood predictive coverage. Existing canonical artifacts were not automatically migrated.

Owns Phase 0–5 of the data-coverage initiative (`notes/data-coverage-implementation/`). The Phase-3 deep package (`deep/`) is the most recently expanded surface.

## Layout

- `cli.py` — `bc-stats` CLI. Subcommands: `prepare-dataset`, `run-eda`, `check-split-leakage`, `check-publication-gate`, `fit-deep`, `fit-pretrain`, `fit-bayes`, `publish-pretrain`, `publish-manifest`, `validate`. `publish-manifest` refuses to write a pointer for a smoke fit (`validate.manifest_is_smoke`: any of the three `is_smoke` markers) with no override flag; refit without `--smoke` and publish that artifact. The fit-deep handler lazy-imports keras and the fit-bayes handler lazy-imports pymc inside the function body so `bc-stats --help` stays Torch- and PyMC-free.
- `dataset_registry.py` — per-dataset metadata for the eight `main_models.model_input_*` views. Most sit at `dataset_version="0.2.0"`; `model_input_advancement` and `model_input_observation_batted_ball` are at `0.3.0`; `model_input_geometry` is at `0.4.0` (the latter two carry the `propensity_p_observed` / `propensity_artifact_id` columns).
- `datasets.py` / `eda.py` — Phase-2 snapshot + EDA producers.
- `model_config.py` / `publication.py` — Phase-2 publication gate.
- `model_configs/` — one `ModelConfig` JSON per registered Bayes target (12 today: 6 obs propensity, 5 geometry, ball_handler), consumed by `bc-stats check-publication-gate`. Each pins `dataset_version` and carries `expected_blocking_findings` (EDA block-severity findings reviewed and accepted, matched by code) plus `addressed_weak_identifications` (`partial_pool` for the obs targets, `drop` for E and D). CAVEAT: `run-eda` stamps the CURRENT registry `dataset_version`, not the frozen version recorded in the dataset artifact's manifest — so config pins must track the registry version, not the manifest.
- `backtests/` — controlled backtest harnesses. `mnar_masked.py` is the MNAR design check: synthetically mask observed events with class-dependent intensity (P(masked) = w_class × per-context intensity), fit corrected (`gamma_propensity_class`) and uncorrected (`gamma_propensity_zero`) variants on the survivors, and gate on recovery of the masked slice's class mix (focal-share relative error reduction ≥ 0.25), held-out non-regression, and sampler diagnostics. Driver: `scripts/mnar_masked_backtest.py`; writes `artifacts/statistical/backtests/mnar/<run_id>/metrics.json` with `overall_pass`. The `gamma_propensity_class` arm is the negative control: it is inert on the masked slice (relative reduction −0.001). It is not wrong-signed — `z` is the standardized logit of P(observed), masked events have low `z`, and a negative focal coefficient raises the focal class there, the direction a correction needs. The harness also evaluates an `offset` arm: a pure post-hoc reweight of the `gamma_propensity_zero` arm's exported per-event class shares by the ORACLE per-class offset `delta_c = logit(clip(w_class[c] · mean(intensity_tiers), eps, max))` (the Task-1 scoring-time mechanism applied to known mask probabilities). The `offset` block in `metrics.json` carries `focal_share_error` (offset vs uncorrected), `relative_reduction`, `tv`, and `pass`; held-out / diagnostics are inherited from the noprop fit (the reweight only touches the masked-slice imputation). Helpers: `oracle_selection_offset`, `reweight_class_shares_per_event`, `evaluate_offset_arm`.
- `mnar_masked.py::MaskConfig.design` registers three robustness designs alongside the default `w_class_intensity` (referee major 2): `covariate_joint` (`P(masked) = w_class · intensity[bucket] · m(covariate)`, `m` a 2-level multiplier on the first present column of `covariate_columns` — typically `batter_hand`, a real fixed effect the geometry model conditions on, so the selection-offset's per-class-only assumption is genuinely violated; the covariate's distinct values are split into the two levels by sorted rank, not a salted hash — a low-cardinality column like `batter_hand` (`{"L", "R"}`) can have both real values collide into the same hash bucket by chance, silently degenerating the design to a level shift); `scorer_blocked` (whole maskable games hashed into a high-rate block, class-independent within block — mimics source-block absence); `era_graded` (intensity assigned by season quantile into the same `intensity_tiers`, oldest seasons at the highest tier, instead of a salted game hash). For any design other than `w_class_intensity`, `run_backtest` scores the offset arm with `realized_class_selection_offset` (the mask's actually-realized empirical per-class masked rate, not the `w_class_intensity`-only closed form `oracle_selection_offset` assumes) — this is each design's honest oracle, deliberately misspecified relative to the true selection process whenever that process depends on more than class alone. For the three class-only designs (`w_class_intensity`, `scorer_blocked`, `era_graded`) the offset arm's recovery is an algebraic identity at the marginal level (`P(c | masked) ∝ P(c | observed) · odds_mask(c)` holds for any per-event shares), so ≈exact / ≈no-op there is a property of the design, not evidence; only `covariate_joint` (`batter_hand`, a conditioned-on covariate) is informative and shows a genuinely partial correction. The recorded results are `SMOKE_BUDGET` runs with the convergence gates failing (ESS 20–47) and no run artifacts checked in. Results + regeneration commands: `notes/paper/tables/mnar_backtest_robustness.md`. Driver flag: `scripts/mnar_masked_backtest.py --mask-design {w_class_intensity,covariate_joint,scorer_blocked,era_graded}`; justfile: `just mnar-backtest` / `just sensitivity-ribbon`.
- `calibration.py` — temperature scaling, isotonic regression, ECE, Brier, reliability curves. Numerical primitives consumed by `bayes/training.py`; `multiclass_expected_calibration_error` / `multiclass_reliability_curve` bin on argmax-class (top-label) confidence — `bayes/training.py::_evaluate_held_out` uses them for every multinomial target's `ece_held_out` metric and the `exports/calibration_curve_topk.parquet` (`CALIBRATION_CURVE_TOPK_EXPORT_FILENAME`) reliability export.
- `sensitivity.py` — MNAR pattern-mixture sensitivity ribbon for the imputation softmax exports. `marginal_shares(export, offset)` event-averages the per-event `shares_c·exp(delta_c)` renormalization (the Task-1 offset mechanism as a post-hoc reweight, no refit); `sensitivity_ribbon(export, dimension)` sweeps each class's selection log-odds over `DEFAULT_GRID` (`±{0.25,0.5,1.0}` nats) and returns the per-class marginal band (`delta=0` reproduces the published MAR marginal); `ribbon_band` collapses to `[low, high]`; `offset_recovers_target` is the TV-to-target check used by the backtest validation; `era_sensitivity_ribbon` runs the sweep within each `era_bucket`; `offset_reaching_share` bisects the single-class sweep for the smallest offset at which a class's corrected marginal reaches a target share (`None` when unreachable), and `bound_offset_table` reports it per era beside the grid ends with a `target_in_grid` flag. The grid is an assumed band, not a data-identified one. Driver `scripts/sensitivity_ribbon.py`: default writes `exports/sensitivity_ribbon.parquet` beside each published `geometry_*` fit; `--bound <anchor-run-dir>` writes the per-era trajectory ribbon plus `trajectory_bound_offset.parquet` (the GroundBall offset at the derived-slice lower bound) beside the trajectory fit; `--validate-backtest <run>` confirms the grid spans the masked backtest's oracle correction. Design + validation: `notes/data-coverage-implementation/mnar-selection-offset-design.md`.
- `mnar_anchor.py` — derived-slice bounds for a geometry dimension's unrecorded slice. `derived_slice_bounds(slice_frame, export_frame)` joins the dimension's event rows (observed + unrecorded) to the published MAR export and returns per-(era, class): `share_lower_bound = n_derived_class / n_unrecorded` (a hard floor: every derived event is an unrecorded event of known class), `share_point_estimate` (truth on derived rows, MAR on the unknown remainder), and `mar_share_on_derived` / `mar_log_loss_on_derived` (the MAR export scored against the derived rows' known class). The derived slice is entirely GroundBall for trajectory, so it does NOT identify a selection offset: `log(p_derived / p_obs)` is `-ln(p_obs_GB)`, a function of the observed slice alone (modeling review H2); the earlier anchored-offset estimator was removed for that reason. `resolve_published_geometry_inputs` finds the frozen dataset (`dataset_artifact_id`) and export behind a published fit; `load_dimension_slice` reads the dimension from that parquet or from `bc.db` read-only. `resolve_published_geometry_inputs(require_dataset=..., require_export=...)` checks only the files the caller will read, so `scripts/mnar_anchor.py --dataset` / `--export` / `--source db` bypass a missing default input. An era with observed rows but no unrecorded rows is emitted with zero counts, `covered = False`, `share_lower_bound = 0.0`, and a NULL point estimate, never a NULL bound. `scripts/sensitivity_ribbon.py --bound` reads `trajectory_artifact_id` from the run's `summary.json` and refuses to pair bounds with a different published trajectory fit. Driver `scripts/mnar_anchor.py` (paper + decade bucketings) writes `artifacts/statistical/anchors/trajectory/<run-id>/{derived_slice_bounds.parquet,summary.json}`; tables: `notes/paper/tables/{groundball_mnar,trajectory_mnar_bound}.md`.
- `validate.py` — cross-phase `validate_artifact()` dispatcher. Reads `manifest.kind` and runs the appropriate check suite. Emits a `ValidationReport`. `find_manifest(artifact_id, roots, *, model_name=None)` is the public artifact-id → `manifest.json` resolver, reused by `scripts/validate_gates.py`. For `kind == "bayes"`, `_grade_held_out_metrics` additionally reads `validation/held_out_metrics.json` when present: held-out ECE above the warn threshold (0.10 smoke / 0.05 default) is a `warn`; a model whose held-out predictive metric (ROC over chance, PR-AUC over the marginal, log-loss under the baseline, or a positive log-lik lift) fails to beat its own baseline is a `block` on a full-scale fit and a `warn` on a smoke fit; a missing or unreadable `held_out_metrics.json` is a `block` on a full-scale fit and a `warn` on a smoke fit, so a full-scale fit with no out-of-sample evidence cannot pass. Smoke is detected from any of the three markers the fit writes (`manifest.metadata.is_smoke`, `bayes_extras.sampler_config.is_smoke`, `diagnostics.json.is_smoke`; `manifest_is_smoke` unions them). `compute_posterior_diagnostics(idata)` is the single convergence-diagnostics pass shared by the fit and the sweep: it reduces r-hat / ESS over every posterior variable up to `DIAGNOSTICS_MAX_ELEMENTS_PER_VARIABLE` (100k) elements (larger ones are skipped and logged), emits the gate pair (`rhat_max` / `ess_bulk_min`, worst element anywhere) and the group-level pair (`group_level_rhat_max` / `group_level_ess_bulk_min`, worst element among variables with at most `GROUP_LEVEL_MAX_ELEMENTS` = 512 elements), and returns the per-variable table that `write_diagnostics_by_variable` persists as `validation/diagnostics_by_variable.json`. `VALIDATION_GATE_VERSION` (currently 2) is the gate's version stamp; bump it whenever a gate is added or its severity changes so every artifact must be re-swept before it publishes as `passed` again. Top-1 accuracy is reported but only ever `warn`s: these targets publish per-event class shares, nothing downstream takes an argmax, and on a skewed class distribution top-1 is pinned to the modal class — `geometry_location_depth` beat the marginal by 0.040 nats while losing top-1 to the modal class by 0.0002. The blocking multinomial check is `log_loss` against `baseline_log_loss`, the entropy of the held-out empirical class shares (the same held-out-empirical convention `baseline_top1_accuracy` uses). `_evaluate_held_out` emits `baseline_log_loss`; for artifacts fit before it did, `_derive_baseline_log_loss` recovers the same quantity from `distribution_calibration.per_position` (rejecting shares outside `[0,1]` or not summing to 1 — a truncated share set yields a finite but understated entropy that would make the gate falsely strict). A non-positive `baseline_log_loss` means a degenerate (single-class) held-out set and is treated as no baseline at all, so the emitted and derived paths agree on degeneracy. Because top-1 no longer blocks, a payload carrying `top1_accuracy` whose log-loss check cannot run (no / non-finite `log_loss`, or no usable baseline) has lost its only blocking held-out gate: that fires `bayes_held_out_log_loss_ungradeable` at the same block-on-full / warn-on-smoke severity. Payloads without `top1_accuracy` (Bernoulli, count/cell) legitimately carry no `log_loss` and stay inert.
- `hdi_coverage.py` — posterior-predictive coverage checks for cell-grain aggregate surfaces. `compute_hdi_coverage` grades held-out realizations against the published parameter HDI — GOTCHA: this number is misleadingly tight against sampling noise (`state_transition` parameter coverage ≈0.21) and undercoverage here is not itself a red flag. `compute_predictive_coverage` (multinomial) / `compute_predictive_mean_coverage` (count/mean) instead simulate a size-matched posterior-predictive draw per held-out cell (truncated-normal parameter layer + conditional-binomial multinomial, `M=2000`) — this predictive number is the primary gate (`state_transition` ≈0.977). `state_transition_coverage_pair` / `run_expectancy_coverage_pair` bundle both flavors per model.
- `scripts/validate_gates.py` (`just validate-gates [model...] [--write]`) — sweeps every published pointer, runs `validate_artifact` on each, and for hooked models (`state_transition`, `run_expectancy`) folds in `hdi_coverage.py`'s predictive/parameter pair; prints one row per model (gate status, the artifact manifest's `validation_status`, and fired finding codes). In both modes it recomputes each Bayes artifact's diagnostics from `inference/posterior.nc` when that file exists and grades the recomputed numbers (via `validate_artifact(..., diagnostics_overrides=...)`, an in-memory overlay on the stored `validation/diagnostics.json`), falling back to the stored file when there is no posterior, so a dry run and a `--write` run reach the same verdict. Read-only by default; `--write` persists the recomputed diagnostics (rewriting the convergence keys of `validation/diagnostics.json` in place and writing `diagnostics_by_variable.json`), then persists `validation_report.json` and stamps the manifest with `validation_status`, `validation_gate_version`, `validated_at`, the recomputed `bayes_extras.diagnostics_summary` pairs, and the re-derived `bayes_extras.weak_identification_flag`. That stamp is the only thing that sets `validation_status` — everything else reads it, and it defaults to `exploratory`, so an artifact that never went through `--write` publishes as `exploratory` no matter how its gates went; and `stamp_estimated_contract` publishes `passed` as `exploratory` unless `validation_gate_version` equals the current `VALIDATION_GATE_VERSION`, so bumping the version forces a re-sweep before anything publishes as passed again. The table's `gate_v` column shows each manifest's stamped version and `weak_id` its flag (recomputed under `--write`). The stamp skips artifacts where status, version, flag, and diagnostics are all unchanged (`validated_at` alone never forces a write), so re-running is free, and skips artifacts whose `kind` has no registered validator (the `validate_no_dispatch` fallthrough) so a missing validator never overwrites a real verdict. It rewrites the raw JSON rather than round-tripping `ArtifactManifest`, because the schema drops undeclared on-disk keys and some older manifests carry a top-level `ablation_status` the schema never modeled. Re-materialize the estimated `@model`s after stamping for the new `confidence_status` to reach the published tables. This is the runnable sweep that replaces the phase-6 markdown validation checklist.
- `manifests.py` — artifact-id generation, atomic manifest read / write, published-pointer resolution rooted at `BC_STATS_PUBLISHED_ROOT` (per-branch) with a global fallback under `artifacts/statistical/published/`.
- `schemas.py` — Pydantic v2 schemas for manifests, datasets, diagnostics, validation, EDA report, validation report.
- `splits.py` — `game_hash_fold(game_id, fold_count)` BLAKE2s splits.
- `leakage.py` — split-registry leakage detection.
- `outputs.py` / `diagnostics.py` — Phase-4/5 hooks (mostly stubs).
- `bayes/` — Phase-4 hierarchical-Bayes runtime. `artifacts.py` lays out `artifacts/statistical/bayes/<model_name>/<artifact_id>/{inference,exports,validation,manifest.json}`. `training.py` exposes `run_bayes_model(...)` which looks up the named target in the registry, builds event-grain inputs via `spec.prep_fn`, samples prior predictive, NUTS posterior (unless `prior_only`) under the configured backend (numpyro for full fits), and posterior predictive, then writes `inference/*.nc`, `exports/{posterior_summary,calibration_curve,event_propensity}.parquet` (Bernoulli targets) or `exports/{posterior_summary,event_credit}.parquet` (multinomial targets), and `validation/diagnostics.json` atomically. `training._posterior_event_means_bernoulli` handles the Bernoulli export path; `_posterior_event_softmax` + `_export_event_credit_shares` handle the multinomial path. `specs.py` defines `BayesTargetSpec` (frozen Pydantic v2): `name`, `dimension`, `dataset_name`, `dataset_dimension_filter`, `outcome_kind ∈ {"bernoulli","multinomial","count"}`, `multinomial_export ∈ {"credit","ball_handler","geometry","pitch_summary","advancement",None}` (routes the multinomial export branch — `outcome_kind` is `"multinomial"` for all of them), `count_export ∈ {"park_factor","run_expectancy",None}` (routes the count export branch; a `@model_validator` enforces `count_export` is set iff `outcome_kind == "count"`), `dl_proposal_dimension` / `dl_class_collapse_positive` / `default_flavors` (gamma_dl flavor gating; a `@model_validator` forces `default_flavors=("gamma_dl_zero",)` when `dl_proposal_dimension is None`), `prep_fn`, `builder`, `sample_size`, `published_manifest_name()`. `sample_size` is the spec-level training row budget (None means "full dataset"); `run_bayes_model`'s resolver picks the smoke-limit kwarg first, then `BC_STATS_SMOKE_LIMIT`, then the `--smoke` default, then `spec.sample_size`. `registry.py` exposes `register_target` / `get_target` / `all_targets`. `targets/observation.py` registers six obs propensity targets — `trajectory_observedness`, `location_side_observedness`, `location_depth_observedness`, `location_edge_observedness`, `general_location_observedness`, `ball_handler_position_observedness`, all with `outcome_kind="bernoulli"`, `sample_size=10_000` (sample-size sweep showed OOS AUC plateau by 10K; 100K only buys +0.016 PR-AUC at 10× wall-clock — see [[phase4-obs-propensity-findings]]). `pulled_opposite` is excluded — purely derived, 0% observed. `targets/credit.py` registers `putout_credit_allocation` + `assist_credit_allocation` (both `multinomial_export="credit"`), `sample_size=10_000`. `targets/ball_handler.py` registers `ball_handler_imputation` (`outcome_kind="multinomial"`, `multinomial_export="ball_handler"`, `sample_size=10_000`) — Model D, sharing the obs dataset + `dataset_dimension_filter="ball_handler_position"` with Model A's `ball_handler_position_observedness` Bernoulli but distinct in `name` / `outcome_kind` / `prep_fn` / `builder` (the registry keys on `name`). `manifest_ingest.py::aggregate_observation_propensity_frames` feeds the `scorer_observation_propensities` SQLMesh `@model`; `aggregate_fielding_credit_frames` (schema `CREDIT_SHARE_SCHEMA`, scoped to `multinomial_export=="credit"`) feeds `imputed_fielding_credit`; `aggregate_ball_handler_frames` (schema `BALL_HANDLER_SCHEMA`, scoped to `multinomial_export=="ball_handler"`) feeds `imputed_ball_handler_probabilities`; `aggregate_geometry_frames` (`GEOMETRY_SCHEMA`, `multinomial_export=="geometry"`) feeds `imputed_batted_ball_geometry`; `aggregate_advancement_frames` (`ADVANCEMENT_SCHEMA`, `multinomial_export=="advancement"`) feeds `imputed_advancement_probabilities`; `aggregate_park_factor_frames` (`PARK_FACTOR_SUMMARY_SCHEMA`, `count_export=="park_factor"`, reads each artifact's `exports/park_factor_summary.parquet`) feeds `park_factor_summary`; `aggregate_run_expectancy_frames` (`RUN_EXPECTANCY_SUMMARY_SCHEMA`, `count_export=="run_expectancy"`) feeds `run_expectancy_summary`; `aggregate_pitch_summary_frames` (`PITCH_SUMMARY_SUMMARY_SCHEMA`, `multinomial_export=="pitch_summary"`) feeds `pitch_summary_distribution`. Every helper always yields at least one (possibly empty) typed frame so the `@model` schema persists before any artifact publishes. Every multinomial helper runs `assert_shares_sum_to_one` on its export (per-grain shares within 1e-6 of 1, `none_share` counted once per event), so a malformed export raises at ingest instead of publishing. A pointer that is present is a promise: if its manifest's `bayes_extras.model_name` is not the spec's name, or its export parquet is missing, `_iterate_published_export_frames` raises (`ValueError` / `FileNotFoundError` with the path) instead of yielding the empty frame, because a restate on a FULL model would otherwise silently empty the production table.
- `models/credit.py` — event-grain PyMC builder `build_fielding_credit_model(inputs, *, priors)` for dual-arm fielding-credit allocation. Per-event softmax `π_{e,k} = softmax(η_{e,k})` over the personnel-eligible position set; per-position `alpha_position` (`ZeroSumNormal` over `position`) plus per-FE × position `delta_<fe>` (`ZeroSumNormal` over position with dims `(<fe>_levels, position)`). No scalar-per-event terms: season / scorer / park / source REs and per-event global FEs would enter every position logit equally and cancel exactly inside the per-event softmax (in both likelihood arms), so the builder omits them. Two likelihoods share `π`:
  - Supervised: `pm.Multinomial("Y_supervised", n=U_sup, p=π[Y_supervised_event_idx], observed=counts)` on unmasked well-attributed events. Load-bearing — provides the per-event signal an aggregate-only arm lacks.
  - Aggregate: `T_target[m] ~ Normal(Σ U_e * π_{e,k}, sigma_box_aggregate)` on the masked subset, at grain `(game_id, fielding_team_id, player_id, fielding_position)`. `T_target` is the deterministic sum of *hidden* `known_credit` over the masked events at that cell (we control the mask, so no authority-source split — single `sigma_box_aggregate`).
  Neither `π` nor `T_pred` is registered as a `pm.Deterministic` (would write 10k × 9 × 4000 × 8 B ≈ 2.9 GB into `posterior.nc` at `sample_size=10_000`). `_posterior_event_softmax` reconstructs `π` analytically from the parameter posteriors. One runtime knob gates fit behavior: `BC_CREDIT_MIN_NATURAL_UNK_RATE=<float>` filters seasons whose per-PBP-source natural-unknown rate falls below the threshold from `_CACHED_NATURAL_UNKNOWN_RATES` — modern 1972+ PBP is essentially 0% natural unknown and contributes no inference scope. (`BC_CREDIT_NONCENTER_SEASON` is gone — it parameterized the per-event `beta_season` RE, which was removed along with the other canceling scalar-per-event terms.) The shipped operating point is `full-10k-v15-tuned` (1% rate floor). The shipped fit lands held-out top-1 ≈ 0.529, TV ≈ 0.01, max per-position abs dev ≈ 0.006 — see `notes/data-coverage-implementation/03-hierarchical-models.md` for the full table and the retraction note on the abandoned `direct_handler_position` lever.
- `models/_credit_data.py` — prep for the dual-arm credit model. `FIXED_EFFECT_COLUMNS = (result_family, base_state_start, outs_start, frame_start, alignment_regime)` — every FE must be populated on more than `PRODUCTION_FE_COVERAGE_FLOOR` (1%) of the production inference target (events with `unknown_credit_need > 0 AND personnel_hard_mask_available AND eligible_for_allocation`); `_assert_fixed_effects_cover_production_slice` runs at the top of `prepare_event_credit_inputs` and raises if any FE falls below the floor. `prepare_event_credit_inputs` filters to well-attributed events (`known_credit > 0 AND personnel_hard_mask_available`), deterministically holds out 10% of GAMES via `game_hash_fold(g, fold_count=10) == 0` for OOS scoring, subsamples the remainder game-level, applies `_apply_synthetic_mask` (per-event Bernoulli ∝ per-position weight × per-(season, source_family) intensity, with a per-game floor of one unmasked event), and emits `EventCreditInputs` with `is_masked`, `Y_supervised_*` arrays (supervised arm), aggregate-arm indicator triples computed from the masked subset's known_credit, and a `HeldOutSet` (true_position + design covariates) for OOS. `REAL_UNKNOWN_RATES_BY_POSITION` (P 1.8%, C 6.9%, 1B 42.2%, 2B 9.0%, 3B 4.3%, SS 7.8%, LF 9.1%, CF 11.1%, RF 7.9%) and `_CACHED_NATURAL_UNKNOWN_RATES` (per-season PBP) are module constants derived once from the upstream authority cache and committed; re-computing requires re-deriving from `credit_authority_targets.parquet`. Aggregate-arm targets are computed from the masked subset's hidden Y rather than the box residual — there is no `materialize_credit_authority_targets` cache. `MIN_EVENTS_PER_SEASON=50` row floor. Multinomial posterior export chunks at `POSTERIOR_CREDIT_CHUNK_DEFAULT=5_000` events at a time (vs `250_000` for Bernoulli) because the `(chain, draw, n_chunk, K=9)` reconstruction array is 9× wider per event.
- `models/observation.py` — event-grain PyMC builder `build_observation_model(inputs, *, priors)`. Linear predictor: alpha + centered random intercept on season (data-dense — ~860 rows/cell at 100k subsample drives a funnel-flip under non-centered) + non-centered random intercepts on scorer / park (and source_family when `len(coords["source"]) > 1`); integer-indexer fixed effects per categorical covariate (`game_type`, `frame_start`, `exposure_status`, `league`, `result_family`, `pa_result`, `leverage_bucket`, `batter_hand`, `pitcher_hand`, `personnel_confidence`, `context_confidence`) drawn from `pm.ZeroSumNormal` over the full level coord (sum-to-zero identification); per-continuous standardized slopes on `outs_start`, `inning_start`, `score_margin`, `leverage_index`, `runs_on_play`, plus paired `is_missing` indicators when any rows were imputed. Likelihood uses `pm.Bernoulli(... logit_p=eta, ...)` directly — no `p_observed` Deterministic in the model graph (would have been 12M events × 4000 draws × 8 B ≈ 380 GB at full scale). No DL covariate. No `event` coord on the model — PyMC infers the event dim from the data length, posterior parameter arrays stay coord-named (`season`, `scorer`, `park`, `<cat>_levels`).
- `models/_event_data.py` — `EventObservationInputs` (frozen Pydantic v2) carrying y, event_keys, random-effect indexers, per-fixed-effect `FixedEffectDesign` (`codes` integer array + `levels` / `reference_level` / `non_reference_levels`; reference is `levels[0]`, non-reference is `levels[1:]`), per-continuous `ContinuousFeature` (standardized + missing indicator + raw_mean/raw_std), and the coord dict. `prepare_event_observation_inputs(parquet_path, *, dimension, smoke_limit, seed)` reads the modeling dataset (which already inner-joins `event_observation_context`), asserts indexer contiguity, and emits the inputs.

### Bayes smoke loop

- `just fit-bayes <model> <dataset-artifact-id> <fit-artifact-id> --smoke` runs `SMOKE_CONFIG` (50 draws × 50 tune × 2 chains, stock PyMC backend) and applies the default 100k-row subsample. `--prior-only` short-circuits before `pm.sample`. Subsampling uses `df.sample(n=N, seed=20260513)` for reproducibility.
- `BC_STATS_SMOKE_LIMIT=N` overrides the row count (mirrors `BC_PRETRAIN_DATASET_LIMIT`).
- `BC_STATS_BAYES_DRAWS` / `BC_STATS_BAYES_TUNE` override `DEFAULT_CONFIG`'s draws / tune (default 1000 / 1000); `_resolve_sampler_config` in `training.py` reads them alongside `BC_STATS_BAYES_BACKEND`, returning the base config untouched when none are set and otherwise rebuilding `SamplingConfig` with the overrides (chains / target_accept / max_treedepth stay at the base). They exist for the case where a model's `alpha_class` intercept ridge slow-mixes under the default and needs longer sampling to clear the default `rhat ≤ 1.05` / `ess ≥ 100` gate.
- `validate-artifact <id> [--model <name>]` dispatches on `manifest.kind == "bayes"` to thresholds in `validate._validate_bayes`: smoke gates (`rhat_max ≤ 1.5`, `ess_bulk_min ≥ 3`, `divergences ≤ 5% of total_draws`, ECE/bucket-dev warn-level only) vs default gates (`rhat ≤ 1.05`, `ess ≥ 100`, zero divergences). The macOS multiprocess-fork-after-Accelerate hang only matters for the PyMC backend; the numpyro backend uses JAX vectorized chains and ignores `cores`. `--model` is required when multiple registered models share an artifact id (all six obs propensity targets use `10k-v1`); without it the validator errors `artifact_id=... is ambiguous`. The default ess gate is 100 (not 400) because the obs propensity design's rare-class FE blocks (`__unknown__` in 3-level cols, NNL/ECL/NN1/NN2 in 8-level `league`) slow-mix as a sampler-efficiency artifact at any N — see [[phase4-obs-propensity-findings]].

### Event propensity export

- `exports/event_propensity.parquet` ships per fit, schema `(event_key: int64, dimension: utf8, p_observed_mean: float64)`. Computed by `_posterior_event_means`: reconstructs `η_e` per event from the posterior parameter draws (alpha + beta_season[s(e)] + beta_scorer[r(e)] + beta_park[p(e)] + delta_full[c(e)] + Σ γ_j x_j(e) + Σ δ_missing_j is_missing_j(e)), sigmoids, and reduces over `(chain, draw)` — one `(chain, draw, chunk_size)` slab at a time. Default chunk 50k. Memory per chunk at full DEFAULT_CONFIG: `4 × 1000 × 50k × 8 B = 1.6 GB` per slab (plus same-size temporaries); the full-coverage export scores ~8–12M events per dimension, so the 250k chunk that predated full-coverage scoring swapped the machine when two scoring jobs overlapped. Smoke fits also score the full dimension (the export is the point of the fit, and the 100-draw smoke posterior makes it ~50 s per 10M events); iterate on synthetic or subsampled datasets when you need a seconds-scale loop. At 12M events × 8 bytes the parquet itself is ~96 MB. The Bernoulli likelihood uses `logit_p=eta` so no per-event posterior tensor is materialized in the model graph.
- No `posterior_predictive.nc` is written: `E[y_rep | data]` is `E[sigmoid(η_e) | data]` analytically for a Bernoulli, so the bucket-deviation calibration check uses `p_mean` directly.
- The published operating point for all six obs propensity targets is `10k-v4-fullscore`: each export covers every event of its dimension in saturated seasons (`ball_handler_position` covers 100% of events; the geometry dims exclude only unsaturated seasons). Held-out ROC-AUC 0.898–0.973 / PR-AUC 0.909–0.992 vs prior baselines 0.374–0.892.
- The `scorer_observation_propensities` SQLMesh `@model` is a thin gather over published `event_propensity.parquet` artifacts: grain `(event_key, dimension)`, columns `(event_key, dimension, p_observed_mean)` plus the eight estimated-metadata contract columns. Materializes a typed empty frame until at least one per-dim Bayes pointer lands.

### Event credit export (multinomial targets)

- `exports/event_credit.parquet` ships per multinomial fit, schema `(event_key: int64, fielding_position: int8, credit_type: utf8, expected_share: float64, none_share: float64?)`. `_posterior_event_softmax` reconstructs per-event `η_{e,k}` from posterior parameters (alpha_position[pos] + Σ delta_<fe>[c_e, pos] across active FEs), softmaxes over the position set, and reduces over `(chain, draw)`. `_export_event_credit_shares` writes the long-form table at the `(event_key, fielding_position, credit_type)` grain. `_export_credit_shares_for_target` decides what gets scored: for both credit types the shipped export is the 463,093-event production slice (`credit_type='putout' AND unknown_credit_need > 0 AND personnel_hard_mask_available AND eligible_for_allocation`), never the training grain — 4,167,837 rows (463,093 × 9 positions), built by `build_production_scoring_frame`. The putout target scores it with the plain `_posterior_event_softmax` over the production rows' own fixed-effect codes. The assist target scores it with `_posterior_event_softmax_putout_marginalized` over the published v1.5 putout posterior (`putout_position` is unknown on the production slice; the marginalization reads the putout artifact's `inference/posterior.nc`, not its export, so the putout export is not an input to the assist fit). The training-grain export is written only as a fallback when the production slice is empty or the assist target has no putout posterior to marginalize over, with a warning. Each event's 9 position shares + `none_share` sum to exactly 1.
- For K=10 fits (assist with a NONE sentinel as position 10), only positions 1..9 are emitted as rows; the per-event `none_share = π_{e,10}` rides along on every position row so downstream consumers can compute `P(any credit) = 1 - none_share` without re-joining the artifact. For K=9 fits (putout), `none_share` is NULL.
- `validation/held_out_metrics.json` ships per credit-allocation fit. Top-1 / top-3 accuracy, log-loss, per-position PR-AUC (1B is near-trivial; OF positions discriminate harder), macro PR-AUC, and the per-position-prior baseline. K=10 fits add an `any_assist` block with `pr_auc` (binary NONE vs ¬NONE) and a `baseline_pr_auc` equal to the empirical ¬NONE rate. Held-out games are the 10% at `game_hash_fold(g, fold_count=10) == 0` and are never seen during training. Use these to pick the operating point on N-sweeps. For the assist target the held-out metrics are putout-marginalized (production-faithful): `putout_position` is observed on held-out events but unknown on the production target, so `_evaluate_held_out` marginalizes over the published v1.5 putout posterior, records a `putout_marginalized: true` flag, and excludes `putout_position` from slice calibration when marginalizing. It also records an `observed_putout_upper_bound` block (metrics conditioned on the true putout) — an upper bound only, not the production metric. **Caveat on held-out PR-AUC.** Per-event FEs that correlate with attribution availability (handler-known events get clean attribution; handler-unknown events are exactly the inference target) inflate held-out PR-AUC without giving production benefit. The 1% production-coverage guard on `FIXED_EFFECT_COLUMNS` is the front-line defense; for any new FE candidate also evaluate the held-out lift restricted to the slice where that FE is NULL.

### Model E geometry imputation

`bayes/targets/geometry.py` registers five specs `geometry_{trajectory,location_side,location_depth,location_edge,general_location}`, all `outcome_kind="multinomial"`, `multinomial_export="geometry"`, `sample_size=10_000`, sharing one prep (`prepare_geometry_inputs`) and one builder (`build_geometry_model`). Per-event K-class softmax over the directly recorded geometry class, scoring the geometry-unobserved slice. The four DL-backed dimensions carry a published DL proposal (`dl_proposal_dimension=<dim>`) and register both `gamma_dl_zero` / `gamma_dl_shrunk` flavors; `general_location` has no DL artifact and is `gamma_dl_zero`-only. @model `imputed_batted_ball_geometry`. Published operating points: `e-noprop-trajectory-shrunk`, `e-noprop-location_side-shrunk`, `e-noprop-location_depth-shrunk`, `e-noprop-location_edge-shrunk`, `e-noprop-general_location-zero` — gamma_dl shrunk on the four DL dims, zero on `general_location`, `gamma_propensity_zero` everywhere.

- `models/geometry.py::build_geometry_model` — generic per-event K-class softmax. Per-class intercept `alpha_class` (`pm.ZeroSumNormal` over the class axis) plus a per-FE `delta_<fe>` (`ZeroSumNormal` over `(<fe>_levels, class)`) for each FE in `FIXED_EFFECT_COLUMNS`. No scalar-per-event terms (season-league / scorer REs) — they would enter every class logit equally and cancel exactly inside the per-event softmax. The optional per-class `gamma_dl * dl_logit` term (`gamma_dl_shrunk` flavor with `inputs.dl_active`) does NOT cancel — the point of carrying it. A parallel per-class `gamma_propensity * z_prop` hook exists: `gamma_propensity` is `pm.ZeroSumNormal` over the class axis, `z_prop` is the standardized logit of `propensity_p_observed`, and the term enters only under flavor `gamma_propensity_class` AND `inputs.propensity_active`. The default flavor is `gamma_propensity_zero`, and the published operating points all use it: the masked backtest showed the learned class flavor does not correct MNAR — it leaves the masked-slice error essentially unchanged (relative reduction −0.001). It is inert rather than wrong-signed: `z` is the standardized logit of P(observed), masked events have low `z`, and a negative focal coefficient raises the focal class on the masked slice, the direction a correction needs. Evidence and mechanism in `notes/data-coverage-implementation/implementation-review.md` (T1.1). The correct MNAR correction is a third flavor `gamma_propensity_offset`: a FIXED per-class selection log-odds offset `delta_c` supplied as data (not learned), applied purely at scoring time — the fit stays observed-only and unchanged. `GeometryInputs` / `GeometryProductionFrame` carry `selection_log_odds_offset: tuple[float, ...] | None` aligned to the class coord order (read from `BC_GEOMETRY_SELECTION_OFFSET` as `label=delta` pairs via `resolve_selection_log_odds_offset`; default None → inert). `_posterior_event_softmax`'s `selection_offset` kwarg adds `delta_c` to `eta[:, k]` before the softmax when the flavor is `gamma_propensity_offset` and the offset is present; an all-zero offset reproduces `noprop` exactly (sensitivity coherence). Per-(era, class) offset is a documented future extension; this pass is per-class only. Design + proof: `notes/data-coverage-implementation/mnar-selection-offset-design.md`. An optional per-class `gamma_handler * z_handler` term (`gamma_handler` is `pm.ZeroSumNormal` over the class axis, scale `GAMMA_HANDLER_SCALE=0.5` module constant) carries Model D's handler posterior into the geometry softmax — it does NOT cancel. `z_handler` is the standardized logit of P(handler is an outfielder) (`logit(share7+share8+share9)` from Model D's published `ball_handler_probabilities.parquet`, joined by `event_key`). The term enters only when `inputs.handler_active` — set in prep when `BC_GEOMETRY_HANDLER` is enabled AND a Model D export resolves — so the shared builder stays inert for Model H (advancement) and any geometry dim without a handler join. DEFERRED: `_posterior_event_softmax` in `bayes/training.py` does not yet reconstruct the `gamma_handler` term, so the production export path must be taught it before a production geometry fit with the handler covariate active can publish. Likelihood `pm.Multinomial("G_observed", n=1, p=softmax(eta))`; no `π`/`η` Deterministic, `_posterior_event_softmax` reconstructs `π` from `alpha_class` + FE deltas (+ active gamma terms).
- `models/_geometry_data.py` — `prepare_geometry_inputs` returns `GeometryInputs` (reuses `FixedEffectDesign` / `HeldOutSet` / `ProductionScoringFrame` from `_credit_data`). Class vocab is dimension-specific: the four DL dimensions use locked ordered constants matching the DL softmax output order; `general_location` derives its vocab from observed-class frequency. FEs are `(result_family, base_state_start, outs_start, alignment_regime, batter_hand)`; `_assert_fixed_effects_cover_production_slice` runs the 1% coverage guard on the geometry-unobserved production slice. 10% game holdout, `MIN_EVENTS_PER_SEASON=50` per season-league cell. KEY: the per-class DL logit (`compute_dl_log_probs_per_class_with_mask`) is CENTERED on the class means of the DL-present training rows (`dl_logit_class_means`, subtracted from present train / held-out / production rows) to break the `alpha_class`↔DL collinearity ridge; rows with a NULL `dl_p_class` stay exactly zero on every slice, so `gamma_dl` contributes nothing for them. The prep logs the DL null rate per slice; `build_geometry_production_frame(gamma_dl_active=True)` raises when the production null rate exceeds `PRODUCTION_DL_NULL_RATE_CEILING` (0.05; the fit must publish `gamma_dl_zero`) and warns on any smaller non-zero null rate — the published trajectory fit logs 0.0000 and the location fits 1.0000, so the ceiling changes nothing shipped. `propensity_active` semantics: the `propensity_p_observed` column absent from the dataset → inactive (warn, z=0); present but 100% NULL on a non-empty training slice → `ValueError` (the dataset predates the published propensity artifacts — re-freeze it). The propensity-logit mean/std are computed on the non-NULL training rows and FROZEN — held-out and production scoring reuse the training stats; NULL rows map to z=0. `handler_active` mirrors the same freeze discipline: when `BC_GEOMETRY_HANDLER` is set, `bayes/handler_covariate.py::load_handler_outfield_logit` resolves Model D's published `ball_handler_imputation` pointer (or `BC_GEOMETRY_HANDLER_ARTIFACT=<artifact dir>` override) and returns `event_key → logit(P(OF))`; the prep joins it, standardizes on the Model-D-covered training rows, freezes mean/std, and maps events absent from Model D's export to z=0. The measurement-error confusion arm (`Ω`/`Δ`) is DEFERRED — UNIDENTIFIABLE: the deduced layer is a deterministic recode of the same scorer's fielding (not an independent second label), so the confusion probabilities cannot be separated from the class prior; same blocker as Model B. See `notes/data-coverage-implementation/implementation-review.md` T2.2.

- `gamma_dl_shift.py` / `scripts/gamma_dl_shift.py` — counterfactual RE-shift diagnostic between a geometry `gamma_dl_zero` fit and its published `gamma_dl_shrunk` sibling. Per publication-tier posterior block (`alpha_class` + each `delta_<fe>`; `gamma_*` coefficients excluded — `gamma_dl` only exists in the shrunk fit) computes `|mean_shrunk - mean_zero| / pooled_sd` per cell (pooled SD `= sqrt((sd_zero²+sd_shrunk²)/2)`) and the share of cells over a 0.25-SD threshold. Driver `scripts/gamma_dl_shift.py --model <name> --zero <id> --shrunk <id> --json <path>`; convention writes `validation/gamma_dl_shift.json` into the zero artifact dir. ### Model F park factors

`bayes/targets/park_factor.py` registers `park_factor_runs` — the first `outcome_kind="count"` target (`count_export="park_factor"`, `sample_size=500_000`). Team-game-grain NegativeBinomial run-scoring model whose sum-to-zero per-(park, season, league) effect is the published park factor. @model `park_factor_summary`.

- `models/park_factor.py::build_park_factor_model` — `team_runs ~ NB(mu=lambda, alpha=phi)` with `log lambda = log(exposure_pa) + alpha_season_league + offense[team-season] + pitching[opp-team-season] + theta_park[park-season-league] + home_adv·is_home`. `theta_park` is the only coord-sized Deterministic — the published park factor (`park_factor_mean = exp(theta_mean)`). KEY identification fix: `theta_park` is the raw per-cell park effect **centered to sum to zero WITHIN each (season, league) group** (`_center_within_group`, a constant one-hot membership matmul — JAX-safe, no scatter-add), not globally across all park-season-league cells; this stops era scoring from leaking into the park effect when `alpha_season_league` under-absorbs. The raw effect optionally follows a **non-centered, gap-aware AR(1) persistence prior along each (park, league) chain of observed cells**. `eps_park_raw ~ Normal(0, 1)` has one entry per published cell (dims `park_season_league`); a chain head is scaled by `sigma_park_init`, every later cell by `sigma_park_innov * sqrt((1 - rho^(2d)) / (1 - rho^2))` where `d = ar_season_gap` is the number of seasons since the previous observed cell of the chain, and `_propagate_ar1` applies `theta_t = rho^d * theta_{t-1} + innovation_t` as one lower-triangular `rho ** (season offset difference)` matmul per chain (`_chain_blocks` sorts cells by `(ar_chain_idx, ar_step_idx)`; blocks total about 120K entries at full scale versus 6.9M for a dense cell-by-cell matrix). A 33-season gap therefore decorrelates the two cells to `rho^33` with the stationary bridging variance, a one-season gap is the plain AR(1), and no latent cells exist for unobserved seasons. `rho_park ~ Beta(2,1)`, `sigma_park_innov ~ HalfNormal(0.15)`, `sigma_park_init ~ HalfNormal(0.3)`. The construction is plain tensor ops, not `pytensor.scan` (a scan whose sequence traces to an RV trips PyMC's prior-predictive RNG-update collection) and not `pm.AR` (its centered parameterization on a padded `(chain, step)` grid left `sigma_park_innov` at ESS 17 / rhat 1.17 and `rho_park` at ESS 50 / rhat 1.05 in `pf-full-ar1-v3`, with 81% of the grid pure prior). Offense / pitching are non-centered per-(team, season) random effects. No team-game-sized Deterministic (no `lambda`). Two builder gates mirror `run_values::_era_regime_enabled`: `BC_PARK_FACTOR_DISABLE_AR1` (off → independent `z_theta_park × sigma_park` raw effect, still season-league-centered) and `BC_PARK_FACTOR_DISABLE_HOME_ADV` (off → drop the HFA term). The HFA term + the `home_idx` road/home split are the sensitivity diagnostic for the home-park/home-team confound.
- `models/_park_factor_data.py` — `prepare_park_factor_inputs` aggregates per-event `model_input_park_factors` to one row per `(game_id, batting_team_id)` with summed `runs_on_play` and `plate_appearances` exposure. Carries `home_idx` (batting team is home), `cell_season_league_idx` (cell → season-league group, for centering), and `ar_chain_idx` / `ar_step_idx` / `ar_season_gap` / `n_ar_chains` (`_build_ar_chains`: the cell's (park, league) chain, its season rank within the chain, and the seasons elapsed since the previous observed cell of that chain, 0 at the head). `MIN_GAMES_PER_PARK_CELL=25` floor drops unidentified park cells; 10% game holdout ships for OOS, levels unseen in training encode to `-1`. DEFERRED — `park_episode_status` is 100% NULL in the dataset, so no `park_episode_id` is derivable to reset the AR(1) chain at structural park changes; the AR(1) keys on (park, league) only. Umpire / weather / surface / day_night spec covariates are DEFERRED — none of those columns exist in `model_input_park_factors` (no umpire id, no weather/temp/wind, no surface, no day_night). Batter/pitcher hand exist per-event but the prep is team-game grain (hand varies within a team-game row), so hand FEs are DEFERRED to an event-grain restructure.
- Export: `_export_park_factor_posterior` (long-form per-(cell, chain, draw) `theta_park`) + `_export_park_factor_summary` (one row per `(park_id, season, league, outcome)` with `theta_mean`/`sd`/HDI, `park_factor_mean`, `ess_bulk`, `rhat`). Eval is `_evaluate_held_out_nb` — posterior-mean NB held-out log-lik lift + RMSE improvement vs a park-removed (`theta=0`) baseline.

### Model G run expectancy

`bayes/targets/run_values.py` registers `run_expectancy` (`outcome_kind="count"`, `count_export="run_expectancy"`). Reuses the count infra. @model `run_expectancy_summary`.

- `models/run_values.py::build_run_expectancy_model` — cell-grain NB. `models/_run_values_data.py` first applies `filter_event_population` (`game_type = 'RegularSeason'`, `inning_start < 9`, `denominator_policy = 'include'` — a game-level exposure gate — and only real events — `result_family IS NOT NULL OR start key != end key OR runs_on_play > 0`, which drops ~1.26M substitution/no-op rows; it raises if the dataset lacks any of those columns. This is NOT the deterministic `run_expectancy_matrix` population: that SQL gates exposure per frame with `QUALIFY NOT BOOL_OR(truncated_frame_flag)` and has no real-event clause), then aggregates `runs_to_end_of_inning` to one row per `season|league|outs_base` cell, where `season`/`league` are the dataset columns (NOT the `season_group`/`league_group` buckets embedded in `run_expectancy_start_key`, which collapse pre-1914 seasons and non-AL/NL/FL leagues to `Other`) so the cell is identical to the state-transition prep's; the sum of `n` iid `NB(lambda, phi[state])` that share a cell mean is `NB(mu=n*lambda, alpha=n*phi[state])`, so the cell-sum likelihood is exact and collapses ~14M events to a few thousand cells. `phi` is per base-out state (dims `state`, same Gamma prior) because the empirical variance/mean ratio ranges from ~2 (bases empty, two outs) to ~1.2 (loaded, zero out). CENTERED `global_mu → mu_state` (24 base-out states) `→ theta_cell` varying-intercept hierarchy; every cell clears `MIN_EVENTS_PER_CELL=25` and every state pools hundreds of thousands of events, so the centered parameterization mixes without a funnel (no zero-sum, so the cell grid may be ragged). `re_value = exp(theta_cell)` is the deliverable. The `sample_size` budget sits above the corpus so a full fit never subsamples.
- Export: `_export_run_expectancy_posterior` + `_export_run_expectancy_summary` (one row per `(state, season, league)` cell with `re_value_mean`/`sd`/HDI, `ess_bulk`, `rhat`). Eval `_evaluate_run_expectancy_held_out` (NB log-lik lift + run-rate RMSE vs a state-only baseline).
- The Markov base-out transition arm ships as the separate `state_transition` target (`bayes/targets/state_transition.py`, `multinomial_export="state_transition"`); see Model G transition arm below. `linear_weights_estimated.py` propagates the RE posterior draws into the `linear_weights_estimated` @model: it joins posterior cells on the transition row's own `(season, league)` plus the key's state suffix, drops transitions whose start state has no posterior cell, and applies the deterministic occurrence floor `DETERMINISTIC_PLAY_FLOOR` (100; `test_linear_weights_estimated.py` asserts it equals the `QUALIFY COUNT(*) OVER result > N` literal in `linear_weights.sql`, so drift fails the suite instead of a materialization) so cells at or below it publish the corpus-pooled per-play value with `is_imputed = True`.

### Model G transition arm (state_transition)

`bayes/targets/state_transition.py` registers `state_transition` (`outcome_kind="multinomial"`, `multinomial_export="state_transition"`, shares `model_input_run_values` with `run_expectancy`). Cell-grain Multinomial over the 25 end classes (24 base-out states + an `inning_end` sentinel) per `(season, league, start_state)` cell. @model `state_transition_summary`.

- `models/state_transition.py::build_state_transition_model` — `Multinomial(n=cell_total, p=softmax(eta))` over a REACHABILITY-MASKED reference-class softmax. Base-out transitions obey a hard structural constraint: outs never decrease within an event, so the reachable end classes for a start state are the base states at out counts `>= start_outs` plus the inning-end sentinel (`_reachable_mask`); structurally unreachable `(start, end)` entries are pinned to `MASK_LOGIT = -30` so their softmax share is ~0 and carry no free parameter. Each start state pins its OWN reference — the modal reachable end class (`_reference_by_start`) — to a zero logit (a universal reference is impossible: class 0 is unreachable from any start with outs ≥ 1). The reachable non-reference logits carry a two-level hierarchy stored flat over reachable-nonref pairs: a per-`(start, end)` `alpha_trans` (`Normal(0, ALPHA_SCALE=3)`, no corpus pooling across start states — they live in different reachable spaces against different references) plus a non-centered per-cell `z_cell * sigma_cell`. `eta`/softmax are built in float64 so the `exp(-30)` masked entries stay representable for the predictive multinomial sampler (float32 rounds `sum(p[:-1])` over 1.0). `cell_class_prob` is the only cell-sized Deterministic; `start_state_prob` (24×25) is the per-start marginal used as the held-out baseline. The prep raises if any observed count lands in a structurally-unreachable entry.
- `models/_state_transition_data.py::prepare_state_transition_inputs` applies the same `filter_event_population` as the run-expectancy prep (so `0_0 -> 0_0` is a home run or no-advance play, never a substitution) and aggregates the per-event corpus to cell-grain length-25 count vectors keyed on the shared `season|league|outs_base` cell label (`cell_label_expr` / `parse_cell_label` from `_run_values_data.py`) and the `(outs, base)` suffix of `run_expectancy_end_key`, and emits `reachable_mask` + `ref_class_by_start`. `hdi_coverage.py`'s two held-out realization extractors apply the same filter so the coverage gate grades the fitted population. `MIN_EVENTS_PER_CELL=25` floor; 10% game holdout; sample budget above the corpus so a full fit never subsamples.
- Export: `_export_state_transition_summary` (one row per `(start_state, season, league, end_class)` with `cell_class_prob` mean/sd/HDI only). At 6,218 cells the persisted `cell_class_prob` Deterministic does not scale, so the dispatch computes the export, then drops `cell_class_prob` from the InferenceData before the netCDF write + the shared model-health summary (the published estimated tier drops ess/rhat anyway). Eval `_evaluate_state_transition_held_out` (per-event multinomial log-lik lift + TV vs the `start_state_prob` baseline).
- Published operating point `state-transition-v3` (`BC_STATS_BAYES_DRAWS=4000 BC_STATS_BAYES_TUNE=2000`, 16000 draws): clears the strict gate — rhat_max 1.016, ess_bulk_min 188, ess_tail_min 490, 0 divergences. Held-out loglik_lift 0.0124, TV 0.070 → 0.044 (−37%). 6,218 cells, 155,450 published rows (24 start states × 116 seasons). The earlier centered/non-centered non-convergence (rhat 4) was a misspecification (treating all 24×25 pairs as reachable), fixed by the mask above — see `notes/followups.md`.

### Model C assist count (assist_count)

### Model J pitch summary

`bayes/targets/pitch_summary.py` registers `pitch_summary` (`outcome_kind="multinomial"`, `multinomial_export="pitch_summary"`). Cell-grain Multinomial over the plate appearance's 12 final ball-strike classes (balls 0–3 × strikes 0–2, `class = balls*3 + strikes`) per `(result_family, season, league)` cell, restricted to the `has_count` slice. @model `pitch_summary_distribution`.

- `models/pitch_summary.py::build_pitch_summary_model` — `Multinomial(n=cell_total, p=softmax(eta))` over a REACHABILITY-MASKED reference-class softmax, the same construction as `state_transition`. Final counts obey a hard structural constraint per result family: strikeouts end with two strikes and walks (intentional walks fold into `walk` upstream) end with three balls; every other family reaches all 12 classes. `_pitch_summary_data.reachable_classes` is the single definition of that rule. Unreachable `(result_family, class)` entries are pinned to `MASK_LOGIT = -30` and carry no free parameter; each family pins its OWN reference (the modal reachable class, `_reference_by_result`) to a zero logit, because `b0_s0` is unreachable for both constrained families. The reachable non-reference logits carry a centered two-level hierarchy stored flat over reachable-nonref pairs: per-`(family, class)` `result_logodds` (`Normal(0, RESULT_LOGODDS_SCALE=3)`, no corpus level across families — they live in different reachable spaces against different references) and per-cell `cell_logodds` centered on it with a shared `sigma_cell`. `cell_class_prob` is the only cell-sized Deterministic; `result_class_prob` is the per-family marginal used as the held-out baseline. The builder raises if any observed count lands in an unreachable entry.
- `models/_pitch_summary_data.py` — `prepare_pitch_summary_inputs` aggregates the `has_count` slice to cell-grain length-12 count vectors. Events recorded in a structurally impossible cell (a few hundred per constrained family in the full corpus) are data errors: they are dropped before the holdout split and the cell floor, with a logged tally per family. Emits `reachable_mask` (families × 12) and `ref_class_by_result`. `MIN_EVENTS_PER_CELL=25` floor; 10% game holdout; sample budget above the corpus so a full fit never subsamples.
- Export: `_export_pitch_summary_summary` (one row per `(result_family, season, league, final-count class)` with `cell_class_prob` mean/sd/HDI/ess/rhat). Impossible classes keep their rows with exactly `0.0` prob mean/sd/HDI and null ess/rhat so the published grain stays complete and each cell still sums to 1. `_evaluate_pitch_summary_held_out` masks held-out counts with the same `reachable_mask` and baselines against `result_class_prob`.
- `models/_pitch_coverage_data.py::prepare_pitch_coverage_inputs` + `models/pitch_coverage.py::build_pitch_coverage_model` — the `has_count` coverage arm: an event-grain `R_i ~ Bernoulli(p_i)` over whether the final count was observed, fit on the FULL `event_level` population (`model_input_pitch_summary` carries both the `has_count` and not-`has_count` rows; ~53% are not observed). Hierarchical logistic mirroring `models/observation.py`: `alpha` + `pm.ZeroSumNormal` over a `season|league` cell (the dense regime, centered) + non-centered `scorer` + `pm.ZeroSumNormal` FE on `result_family` / `alignment_regime`. `logit_p=eta` directly (no per-event `p` tensor). 10% game holdout. The dataset is single-source (`source_family`/`source_type` are single-valued), so no source random effect enters and a single-level FE is skipped. This arm is NOT wired through `bayes/training.py` (no spec / CLI target — deferred export wiring); smoke it via a standalone `pm.sample` script.
- Summary-model context terms: `source_family`/`source_type` are single-valued in this dataset, so a source partial-pooling level on the cell-grain summary hierarchy is degenerate (one level) and is NOT added. Per-batter/pitcher context is only expressible at event grain (18K batters / 10K pitchers); the summary model is cell-grain over `(result_family, season, league)` and cannot carry it — DEFERRED to an event-grain restructure.

## Deep package (`deep/`)

Train deep proposal distributions and embeddings on frozen modeling datasets so Phase-4 Bayes models can consume out-of-fold deep outputs as regularized inputs. **Deep outputs never publish as facts.**

- `__init__.py` — sets `KERAS_BACKEND=torch` via `os.environ.setdefault` so any deep import lands on Torch.
- `target_spec.py` — `DeepTargetSpec(BaseModel, frozen=True)`. Required fields: `name`, `dataset_name`, `target_column`, `weight_column`, `kind ∈ {multiclass, binary}`, `proposal_dimension` (drives `published_manifest_name()` and the `dimension` column on the sibling manifest). Optional `filter_predicate` (DuckDB SQL on the dataset frame). Opt-in `pretrained_embeddings_artifact_id` + `freeze_pretrained_embeddings` warm-start the per-target Embedding layers from a `kind="pretrain"` artifact post-`build_model`.
- `feature_layout.py` — re-exports `FeatureLayout` from `ml.features` and provides a per-dataset registry. Each target's first import triggers `register_coverage_layout(...)` as a side effect. Also exports `validate_pre_event(layout)`; every `_register()` calls it before publishing the layout. The deny-list rejects post-event / outcome-correlated columns (`*_end`, `*_on_play`, `pa_result`, `result_family`, `fielder_chain`, `gap_class`, `fielding_evidence_status`, `batted_to_fielder*`, `hit_or_out`, `balls_called`, `strikes_*`, `swings*`, `pitches*`).

- `io.py` — Parquet loader + `add_kfold_id` (delegates to `splits.game_hash_fold`) + `assert_game_group_invariant` and `assert_export_partition_invariants` write-time checks (partitions disjoint; every OOF row's `fold_id` re-derives from its game hash). The fold runner stamps `fold_id` on every exported row (null outside OOF) and raises rather than ever exporting full-fit predictions under the OOF partition (`fold_count >= 2` is enforced on `DeepTargetSpec`).
- `training.py` — fold runner. For each target: `fold_count` OOF fits + 1 full fit. Writes `probabilities.parquet`, `class_labels.json`, `manifest.json` atomically.
- `artifacts.py` — atomic writes under `artifacts/statistical/deep/<target>/<artifact_id>/`.
- `manifest_ingest.py` — `aggregate_proposal_manifest_frames(sibling)` feeds the `dl_*_proposal_manifest` SQLMesh `@model` files. Always yields at least one (possibly empty) frame so the typed schema persists.
- `embeddings.py` — extraction + parquet export + `aggregate_embedding_frames` for the `dl_embedding_artifact` @model.
- `pretrain/` — shared entity-embedding pretrain via two-stage residual decomposition. See [[pretrain-architecture]] memory entry for the full architecture. `spec.py` defines `PretrainSpec` + `HeadSpec` (the `PretrainSpec.row_filter_predicate` field carries a polars-SQL predicate applied pre-partition). `heads.py` does per-head encoding with NULL-mask `sample_weight`s.

  **Two-stage fit.** Stage 1 trains the trunk + heads on a context-only layout (no entity IDs, no observed-outcome inputs). `scripts/pretrain_emit_offsets.py` loads the saved stage-1 `model.keras` (with `compile=False`), builds an inference submodel whose outputs are the per-head `{head}_logits` intermediate Dense layers, streams the dataset through `.predict()`, and writes one float16 parquet per head under `artifacts/statistical/deep/<stage1_spec>/<stage1_id>/offsets/<head>.parquet` with columns `event_key, logit_0 .. logit_{K-1}`. Stage 2 runs the full architecture (with batter+pitcher embedding group + observed outcomes as inputs) with `BC_PRETRAIN_OFFSET_ARTIFACT=<stage1_id>` set: `pretrain/training.run_pretrain` joins the per-head offsets onto the dataset by `event_key`, encodes `x[f"offset_{head}"] = float32 (N, num_classes)`, overrides head class labels with stage-1's manifest so cached logits align by index, and passes `offset_inputs={...}` to `build_pretrain_model`. Loss path is `CE(softmax(stage1_logits + Δ_logits), label)` so the embedding only learns the residual / interaction signal not predictable from context alone.

  **Active spec.** `targets.py` registers two spec names: `event_universe` (full layout) and `event_universe_context` (stage-1 context-only layout). Both share the 5-head spec and the batted-ball row filter. Full layout: embedding group `('player', ('batter_id', 'pitcher_id'))` plus ungrouped `park_id` / `scorer`; low_card / numeric intentionally include post-event observed outcomes (`pa_result`, `outs_on_play_capped`, `runs_on_play_capped`, `r1/r2/r3_advancement`). `validate_pre_event` is NOT called on pretrain layouts for this reason. Heads (5, all imputation targets): `trajectory_remapped`, `batted_location_general`, `batted_location_depth`, `batted_location_edge`, `batted_to_fielder_class`. Row filter: `pa_result IN (<11 batted-ball outcomes>)`.

  **Training config.** `training.py` honors split optimizers (trunk Adam 1e-3, embed Adam 5e-3→1.5e-3), Kendall-Gal uncertainty weighting, `BC_PRETRAIN_LOSS=focal` (γ via `BC_PRETRAIN_FOCAL_GAMMA`), and `BC_PRETRAIN_USE_HARD_HEAD_ES=1` with `BC_PRETRAIN_HARD_HEADS=...` (default `trajectory_remapped,batted_location_general,batted_to_fielder_class` for the active 5-head spec). Smoke knob: `BC_PRETRAIN_DATASET_LIMIT=<N>` deterministically subsamples both stages with `df.sample(n=N, seed=0)` so stage-1 / emit / stage-2 agree on rows.

Pretrain training-time diagnostic probes (the historical `SlashLineProbe` / `FieldingProbe` / `OutfieldArmProbe` / `LinearProbeDownstreamCallback` / `MonteCarloSlashProbe`) were removed when the pretrain head set dropped `pa_result`. ### Pretrain invariants

- **Pre-event inputs only on downstream supplements.** Every supplement's `FeatureLayout` must contain only features observable at inference time. Post-event columns (`fielder_chain`, `pa_result`, `result_family`, `batted_to_fielder*`, `outs_on_play`, `runs_on_play`, `*_end`, cumulative AB pitch/swing counters, `gap_class`, `fielding_evidence_status`, `hit_or_out`) train to a distribution that does not exist at scoring time and let the model shortcut entity priors. `validate_pre_event` enforces a deny-list and is called from every supplement's `_register()`. The pretrain layout is exempt. See [[pretrain-architecture]].
- **Time-forward gate eval.** Permutation-importance and acceptance gates run on `time_forward_fold = 'VALIDATE'` (season = 2023). Use `scripts/permutation_importance_generic.py --time-forward`. The training split stays on `primary_fold` (HASH(game_id)) to maximize data.
- **Pretrain head set.** Heads cover only imputation targets (data genuinely missing in retrosheet). Fully-observed outcomes go in the input set, not the head set. See [[pretrain-architecture]] for the rationale and current head list.
- **Pretrain → supplement gate.** No-pretrain baseline ran per supplement on the stripped layout sets the gate floor; pretrained artifact must hit ≥ ×1.5 batter-side Δ_CE and not regress on park / pitcher. Recorded under `notes/data-coverage-implementation/phase3-acceptance-gates-v6.md` (filename label is incidental).
- **Training labels = directly recorded only.** Modeling-dataset SQL (`model_input_geometry`, `model_input_event_universe`, `model_input_advancement`) uses `observed_status = 'observed'` (not `IN ('observed', 'derived')`) and `class = raw_value` (not `COALESCE(raw_value, deduced_value)`). Heuristic deductions in `calc_batted_ball_type` (HR→Fly, OF-putout→AirBall, infielder-assisted-putout→GroundBall, fielder-position-derived location_side/depth) and `event_observation_geometry` still surface for analyses / published aggregates; they are excluded from the DL training-label path so pretrain heads + downstream supplements train only on what was directly recorded. The `pulled_opposite` dimension is purely derived (zero eligible rows under this rule).
- **Downstream embed-dim env.** Geometry fits need `BC_DEEP_FORCE_EMBED_DIM=128` to match the pretrain's capped 128-D player embedding. Combine with `BC_PRETRAIN_SKIP_DIM_MISMATCH=1` so the ungrouped `park_id` (pretrain dim 17) and `scorer` (pretrain dim 95) layers skip warm-start instead of failing. Tracked as a follow-up in `notes/followups.md`.

- `imputed_advancement_probabilities.py` — grain `(event_key, baserunner, advancement_class)` (Model H). Thin gather over `aggregate_advancement_frames`; keyed by baserunner slot, no personnel join.
- `park_factor_summary.py` — grain `(park_id, season, league, outcome)` (Model F). Thin gather over `aggregate_park_factor_frames`; drops the diagnostic `ess_bulk` / `rhat` columns from the published summary.
- `run_expectancy_summary.py` — grain `(state, season, league, outcome)` (Model G). Thin gather over `aggregate_run_expectancy_frames`.
- `pitch_summary_distribution.py` — grain `(result_family, season, league, final_count_class)` (Model J). Thin gather over `aggregate_pitch_summary_frames`.
- `state_transition_summary.py` — grain `(start_state, season, league, end_class)` (Model G transition arm). Thin gather over `aggregate_state_transition_frames`.

Every `@model` reads its rows via the corresponding `manifest_ingest.aggregate_*` helper. The test suite hits the helper directly because importing `@model` files without a SQLMesh context fails to parse the project dialect (`UINTEGER` is not parsed in stock sqlglot).

### Publication tiers + estimated-metadata contract

- `publication_tiers.py` — `PublicationTier` enum (`official` / `deterministic` / `estimated` / `synthetic` / `withheld`) and `PUBLICATION_TIERS: dict[str, PublicationTier]` mapping unqualified published `main_models.*` names to tiers. The twelve data-coverage coverage tables are `estimated`; the three legacy point surfaces (`linear_weights`, `park_factors`, `run_expectancy_matrix`) are `deterministic`. `tier_for(name)` accepts qualified or unqualified names; `estimated_model_names()` returns the twelve. The registry is the declared tier source; the contract stamp (`manifest_ingest`) and the `estimated_contract_complete` audit currently enforce the contract directly — deriving their target sets from the registry is a tracked follow-up.
- `manifest_ingest.stamp_estimated_contract(frame, manifest, *, method, observed_status="estimated")` stamps the eight contract columns onto every estimated frame: `artifact_id` (= `manifest.artifact_id`, replaces the old `bayes_artifact_id`), `model_name` / `model_version` / `weak_identification_flag` (from `manifest.bayes_extras`), `source_snapshot_id` (top-level manifest), `method` (per-family: `hierarchical_bayes_softmax` for multinomial shares, `hierarchical_bayes_nb` for the count/distribution summaries, `hierarchical_logistic` for the Bernoulli propensity/coverage targets), `observed_status` (constant `estimated`), `confidence_status` (= `manifest.validation_status`, except that `passed` is published as `exploratory` with a WARNING naming the artifact when `manifest.validation_gate_version` is absent or differs from `validate.VALIDATION_GATE_VERSION`; `confidence_status_for` is the rule). The pitch-summary table stamps `hierarchical_bayes_softmax` — it is a 12-class multinomial, not a count model. `ESTIMATED_CONTRACT_SCHEMA` is the shared `{col: pl.DataType}` fragment spread into every `*_SCHEMA`. The diagnostic `ess_bulk` / `rhat` columns no longer ride the published estimated tier (run-expectancy / pitch-summary builders drop them; park already did) — diagnostics live under `validation/`.
- `BayesArtifactExtras.weak_identification_flag: bool` is the publication-gate flag the stamp reads. `run_bayes_model` populates it at fit time and `just validate-gates --write` recomputes it from `inference/posterior.nc`, both via `validate.diagnostics_indicate_weak_identification` on the GROUP-LEVEL pair (`group_level_rhat_max` / `group_level_ess_bulk_min`: the worst element among posterior variables with at most 512 elements), not the all-variable gate pair, so thousands of per-cell or per-scorer elements cannot set the flag while a slow-mixing pooling hyperparameter such as `rho_park` or `phi` can. True when the fit is convergent-but-weakly-identified: group-level `ess_bulk` below `weak_identification_thresholds()` (a config-driven multiple of the convergence gate's ESS floor: `_WEAK_IDENTIFICATION_ESS_BULK_MULTIPLIER=4×`, i.e. 400 default / 12 smoke), `rhat_max` above the half-margin comfort band (`_WEAK_IDENTIFICATION_RHAT_MARGIN_FRACTION=0.5`, i.e. 1.025 default), any divergences, or non-finite diagnostics (fail-safe). Thresholds derive from `validate._BAYES_THRESHOLDS_{DEFAULT,SMOKE}`, not parallel constants.
- Audit `bc/audits/estimated_contract_complete.sql` is wired onto all twelve estimated `@model`s: a typed-empty table passes (no rows), a populated one must carry all eight contract columns non-null.

## Manifest path discovery

`manifests.find_published_manifest(name)` resolves a model name to its published-pointer path. Resolution order:

1. `BC_STATS_PUBLISHED_ROOT` (per-branch root). Set by the justfile recipes to `artifacts/statistical/published-<branch_slug>/`.
2. `BC_STATS_GLOBAL_PUBLISHED_ROOT` (cross-branch fallback), default `<artifacts root>/published/`. Both env vars resolve through `config.resolve_published_roots()` (the global one via `resolve_global_published_root()`); the defaults keep production behavior unchanged.

The artifacts root is `config.resolve_artifact_root()`: `BC_STATS_ARTIFACTS_ROOT` when set, else `artifacts/statistical/` in this checkout. The CI publish workflow sets it so a fresh checkout resolves the canonical pointers (see `scripts/CLAUDE.md`). `read_published_pointer` resolves a relative `manifest_path` against that root and returns absolute values unchanged; `write_published_pointer(..., relative=True)` stores the path relative to the root (raising if the manifest lives outside it). Readers that call `PublishedPointer.model_validate_json` directly (`deep/manifest_ingest.py`, `deep/embeddings.py`, `scripts/check_phase3_exit.py`) only support absolute pointers until they switch to `read_published_pointer`; `bayes/manifest_ingest.py`, `bayes/training.py` (`_resolve_published_putout_idata`), `mnar_anchor.py` (`resolve_published_geometry_inputs`), and `scripts/sensitivity_ribbon.py` go through `read_published_pointer` and accept either form. The module-level `DEEP_ROOT` / `BAYES_ROOT` / `DATASETS_ROOT` constants still point at the checkout; only pointer resolution follows the env var.

`find_published_pretrain(name)` mirrors this but resolves under the `pretrain/` subdir of each root.

Tests use `monkeypatch.setenv(cfg.ENV_PUBLISHED_ROOT, ...)` to redirect the branch root to a tmp path. `bc/tests/statistical/conftest.py` carries an autouse fixture that also redirects the global root (`ENV_GLOBAL_PUBLISHED_ROOT`) to an empty tmp dir for every statistical test, so no test resolves the machine's real `artifacts/statistical/published/` pointers — the suite is hermetic and order-independent. `cfg.DEEP_ROOT` / `cfg.BAYES_ROOT` are referenced via attribute access in `validate.py` and CLI handlers so `monkeypatch.setattr(cfg, "DEEP_ROOT", tmp_path)` propagates at call time.

## Tests

Under `bc/tests/statistical/` (CLI, prepare-dataset, run-eda, publication gate) and `bc/tests/statistical/deep/` (deep package). The fold runner test is marked `@pytest.mark.slow` because it imports Keras + Torch.

`pytest -m "not slow"` is the default fast tier. `pytest -m slow` runs the fold-runner tests. Full `pytest bc/tests` runs everything. CI scopes via these markers.

## Conventions

- Pydantic v2 `BaseModel` for any schema with validation or serialization.
- `logging.getLogger(__name__)` with module-level `_log = ...`.
- No `print()` in library code. The CLI's structured-log info messages are the audit trail.
- Atomic writes via `tempfile.mkstemp` + `os.replace` for any file the publication gate reads.
- Lazy `import keras` and `import sklearn` inside function bodies so `bc-stats --help` does not pay the cost.
